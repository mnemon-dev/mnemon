# v0.5.3: Actionable Version Maintenance

[简体中文](../../zh-CN/releases/v0.5.3.md) | **English**

v0.5.3 improves status-page version maintenance, clarifies ownership of Host execution and Source presentation, and refreshes the documentation shipped with the official packages. It includes [PR #190](https://github.com/omdsh-dev/dsh-mnemon/pull/190), [PR #191](https://github.com/omdsh-dev/dsh-mnemon/pull/191), and [PR #192](https://github.com/omdsh-dev/dsh-mnemon/pull/192).

## Version maintenance

- The version dialog distinguishes missing, unreadable, outdated, current, locally newer, and restart-pending installations. Registry failures leave local installation guidance available.
- Mnemon CLI installation and migration use the official `@mnemon-dev/mnemon` npm package. An npm-managed CLI can update after the Host verifies that the active launcher belongs to the current npm installation. Homebrew and Go updates remain supported.
- Native execution and version checks share the Memory Spaces package's public CLI discovery entry. Verified Windows npm launchers run through Node without invoking arbitrary shell scripts.
- dsh-mnemon subpackages are collapsed initially. Expand them to inspect Source, Strategy, and Provider versions, the Starter's pinned versions, and the owning Profile. Independently installed packages can update in that Profile; Starter dependencies update with the Starter, and source links remain intact.
- Updates honor management authorization and read-only configuration, reject concurrent writes, verify the resulting installed version, and keep a restart reminder until the Host restarts.

## Ownership and documentation

Host turn and maintenance execution now share explicit ownership and cleanup, including background-to-foreground handoff and Node 20-compatible public execution helpers. Source packages own their default page copy and layout assets. Memory Spaces configuration and optional Strategy validation use their owning public helpers while preserving existing defaults.

The compact workbench header no longer overlaps longer translated titles. Published READMEs and the bilingual documentation explain the composable-memory boundary, installation, independent packages, and data scope, with real DSH screenshots and verified navigation.

## Packages and upgrade

This release advances the Starter and all sixteen official plugins to `0.5.3`: each package has changed published content, including its README. Packages continue to use independent versions; unchanged packages will not be republished merely because the Starter advances.

Install the exact release in the owning DSH Profile and restart it:

```sh
dsh plugin --profile web add dsh-mnemon@0.5.3
```

Use `headless` instead of `web` for a Headless Profile. The Starter installs its exact tested plugin composition on the npm `latest` channel. Install or migrate Mnemon CLI separately in the Host's terminal, with Node.js 22 or later:

```sh
npm install --global @mnemon-dev/mnemon@latest
mnemon --version
```

If an older CLI remains active, review `PATH`, `MNEMON_CLI_PATH`, and the configured `cliPath` before restarting DSH. See [Getting started](../guides/getting-started.md) and [Operations](../guides/operations.md).

## Compatibility, verification, and rollback

Existing Entry ids, configuration, storage paths, memory formats, and Provider data remain valid. No data migration is required. Before upgrading, back up the effective memory root, workspace Documents, DSH Profile/configuration, and separately managed Provider data as described in Operations.

The implementation passed 783 root tests, workspace verification, deterministic builds, real isolated DSH Headless activation, and independent verification of sixteen plugin repositories and seventeen packed artifacts. The [status-page evidence](../../pr-assets/status-version-maintenance/README.md) records real desktop and mobile version-dialog checks. Windows launcher behavior uses simulated filesystem/process fixtures; the opt-in real Native and Windows binary tests require their separate environments. This does not remove the [documented narrow-screen settings limitation](../reference/compatibility.md).

The release workflow verifies and freezes the versioned artifacts, publishes dependency layers before the Starter, installs the complete composition from npm, and smoke-tests a Registry upgrade from v0.4.7 before creating the GitHub Release.

To roll back, install `dsh-mnemon@0.5.2` in the same Profile and restart DSH. No data conversion is needed. Independently maintained Profile packages and the separately installed CLI must be restored separately if they were changed.
