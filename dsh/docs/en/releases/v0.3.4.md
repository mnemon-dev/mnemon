# v0.3.4: Scoped Runtime Memory and Capacity Controls

[简体中文](../../zh-CN/releases/v0.3.4.md) | **English** | [Capability map](../guides/capabilities.md)

v0.3.4 makes Runtime Memory boundaries explicit across storage roots, git branches, and capacity budgets. It also hardens multi-target archival and restores guided memory reminders after a conversation rewind.

## Added

- `mnemon.runtimeUserScope: global` can now combine the global root's User Profile with Working Memory from the selected workspace or custom root. User writes and USER compaction stay global, while project writes, MEMORY compaction, Documents, Memory Spaces, and Provider state remain selected-scope. The default `storage` mode preserves the previous single-root behavior. This resolves [Issue #77](https://github.com/omdsh-dev/dsh-mnemon/issues/77) through [PR #103](https://github.com/omdsh-dev/dsh-mnemon/pull/103).
- Working Memory entries can carry an optional git `branches` list through the model tool, RPC, and Web add/edit forms. Each turn projects a scoped entry only on a matching checked-out branch; unscoped entries, User Profile entries, non-git workspaces, detached HEAD, and branch-detection failures retain the previous all-visible behavior. The complete JSON and Markdown sources remain visible and unchanged, while compaction preserves the scope and archival emits `branch:<name>` tags. This resolves [Issue #93](https://github.com/omdsh-dev/dsh-mnemon/issues/93) through [PR #91](https://github.com/omdsh-dev/dsh-mnemon/pull/91).
- `mnemon.runtimeMemory` now configures the complete `MEMORY.md` and `USER.md` UTF-8 byte limits plus the completion-token budget for Runtime migration and compaction workers. Defaults remain 10,240 bytes, 4,096 bytes, and 8,192 tokens; validated custom limits are shared by Runtime writes, Pack operations, and background maintenance. This resolves [Issue #96](https://github.com/omdsh-dev/dsh-mnemon/issues/96) through [PR #102](https://github.com/omdsh-dev/dsh-mnemon/pull/102).

## Fixed

- When a model fails while routing a multi-target Runtime archive, the Host now routes that batch deterministically to the default writable Memory Space instead of abandoning the complete capacity transaction. Caller cancellation still aborts without Provider writes, invalid routes still fail Host validation, and mixed failed/successful batches retain the first successful delegated run's attribution without double-counting migration. This was delivered through [PR #84](https://github.com/omdsh-dev/dsh-mnemon/pull/84).
- A guided memory reminder removed from the model-visible surface by rewind is composed again on the next first step. Hosts without a surface projection retain the previous session-scoped fallback, and reminder text, ordering, and guided-turn accounting are unchanged. This was delivered through [PR #88](https://github.com/omdsh-dev/dsh-mnemon/pull/88).

## Compatibility and upgrade

No persistence migration is required. Existing configuration keeps the v0.3.3 behavior: User Profile follows `storageScope`, Runtime entries remain visible on every branch unless explicitly scoped, and the established capacity and worker limits remain active unless overridden. Both roots keep their complete existing JSON and Markdown data when the global-profile overlay is enabled; changing the setting never copies, merges, or deletes entries. A workspace Mnemon Pack intentionally excludes the separate global User Profile, so back up the global root separately when using this mode.

Update `dsh-mnemon`, restart each DSH profile that uses it, and reopen the Memory System surface. Rollback to `0.3.3` needs no reverse migration. Older versions ignore the new configuration keys and preserve the on-disk data; branch-scoped records remain readable but become visible on every branch until v0.3.4 is restored.
