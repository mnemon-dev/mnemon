# v0.2.7: Isolated Subagent Results

[简体中文](../../zh-CN/releases/v0.2.7.md) | **English** | [Capability map](../guides/capabilities.md)

v0.2.7 restores supervised memory operations on DSH 0.1.0-rc.6 while preserving strict subagent tool isolation.

## Fixed

- Each delegated Mnemon run now registers a unique inherited result tool whose parameters exactly match the operation's result schema.
- The one-run result tool is explicitly admitted by the existing `toolFilter`; recall, write, review, placement, migration, compaction, Document archive, and metadata tasks keep their original hard tool allowlists.
- The parent validates the result schema and child identity, rejects duplicate or missing completion calls, handles nested code-mode completion, and unregisters the tool and event listener after the run.
- This replaces the dependency on DSH's late-injected `structured_output` path that could become unreachable after child tool filtering and cause `memory subagent stopped with error`.

## Compatibility

- The fix is entirely inside dsh-mnemon and does not require a DSH change.
- Public tool contracts, storage layouts, Memory Space schemas, Provider configuration, and persisted data are unchanged.
- The issue affected the shared delegated-result path, so the fix applies to all supervised Mnemon operations rather than only `mnemon_recall` and `mnemon_remember`.

## Verification

- The complete suite passes with 334 tests; one Windows-only smoke test is skipped only on non-Windows local runs.
- Deterministic builds, Headless activation, package checks, and CI on Ubuntu and Windows pass.
- Real WebUI testing covered Agent Query and a conversation-level `mnemon_recall`: the child used only its admitted read tools, invoked its unique result tool, and returned the validated structured result to the parent Agent.

## Upgrading

Update dsh-mnemon and restart the affected DSH profile. No data migration is required.

See the [v0.2.6 release notes](./v0.2.6.md) for the previous patch release.
