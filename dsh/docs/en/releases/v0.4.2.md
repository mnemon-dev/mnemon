# v0.4.2: Shared Builtin placement and canonical settings

[简体中文](../../zh-CN/releases/v0.4.2.md) | **English** | [Configuration](../reference/configuration.md)

v0.4.2 restores optional conversation placement for the Sidebar-first memory workspace. It does not restore a separate legacy UI or include the planned v0.5 view-based architecture. [#142](https://github.com/omdsh-dev/dsh-mnemon/pull/142), [#139](https://github.com/omdsh-dev/dsh-mnemon/issues/139)

## Changes

- **One workspace, two placements.** Sidebar remains the default. Choose Builtin in Settings to show the same pages, dialogs, and styling in a conversation tab; changes apply live and the entries never mount together.
- **Automatic session scope.** Builtin hides the scope badge, workspace picker, and alignment controls. Global storage remains shared, workspace storage follows the owning session's cwd, and custom storage uses `dataDir`. Reads, writes, and independent tasks use the existing Host routing; the global USER.md exception is unchanged.
- **Canonical `builtin` spelling.** The historical `buildin` value is accepted but normalized to `builtin` in runtime/UI state and saved through DSH's revision-fenced settings writer. Startup, external settings edits, and old-client RPC writes are covered. Comments and unrelated fields are preserved; a concurrent newer Sidebar choice wins.
- **Safe lifecycle behavior.** `tabEnabled` controls the selected placement. Conversation shortcuts open the matching entry, and changing sessions clears stale data and editors without changing stored memories.

## Upgrade and compatibility

Install `dsh-mnemon@0.4.2` in the owning DSH profile, then restart that profile. To embed the workspace in each conversation:

```yaml
mnemon:
  displayMode: builtin
  storageScope: workspace
```

- **Retained preferences become effective again.** v0.4.0–v0.4.1 ignored `displayMode: buildin`; v0.4.2 restores it and saves `builtin`. Select Sidebar if you want to retain the standalone entry. An omitted display setting still defaults to Sidebar.
- Profile-only aliases receive a canonical user-setting override; profile files are not rewritten. A read-only settings provider recognizes the alias without bypassing its permissions. Persistence failures are logged without disabling the normalized entry.
- Runtime, Documents, Memory Spaces, Pack formats, storage paths, Provider credentials, and RPC authority are unchanged. The only automatic migration is the display preference, not memory data. Existing v0.4.1 fixes remain included.
- Published DSH 0.1.1-rc.2 remains the dependency baseline; DSH 0.1.2-alpha.1 remains a source-only compatibility target.

## Rollback

Reinstall `dsh-mnemon@0.4.1` and restart the same profile. It ignores `displayMode` and returns to Sidebar without a data conversion. For a rollback to v0.3.x, first use its legacy `buildin` spelling or `sidebar`, since those versions do not accept canonical `builtin`.
