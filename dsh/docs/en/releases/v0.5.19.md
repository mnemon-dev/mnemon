# v0.5.19: DSH 0.2, Desktop Memory and a Guided First Install

[简体中文](../../zh-CN/releases/v0.5.19.md) | **English**

This patch release contains the two pull requests merged after v0.5.18:

- **DSH 0.2.0-rc.1 support** ([#311](https://github.com/omdsh-dev/dsh-mnemon/pull/311)): DSH checks every `@deepseek-ai/dsh` and `@deepseek-ai/dsh-*` peer range before it installs a plugin and whenever a profile starts, and earlier releases declared DSH 0.1.7 only, so DSH 0.2 refused them. The Starter and the Memory Spaces Source now accept `^0.1.7-rc.2 || ^0.2.0-rc.1`, and a test runs DSH's own check for both runtimes.
- **Manage memory in DSH Desktop** ([#310](https://github.com/omdsh-dev/dsh-mnemon/issues/310), [#311](https://github.com/omdsh-dev/dsh-mnemon/pull/311)): Desktop windows load from the app's own `dsh-app://app/` address. Mnemon treated them as remote pages, so with the default `remoteAccess: read-only` the Memory System and the plugin settings were read only while agent tools could still write. Application windows now use Mnemon's local channels. Pages opened from another device keep the read-only default and now say which grant and restart they need.
- **Status on a fresh install** ([#311](https://github.com/omdsh-dev/dsh-mnemon/pull/311)): Mnemon Native names the CLI version instead of waiting for it indefinitely.
- **Consistent memory interactions** ([#307](https://github.com/omdsh-dev/dsh-mnemon/pull/307)): the turn memory bar and Save to memory carry the Memory System's brain mark; the bar names what each tool did and each item opens where it lives. Save to memory is one dialog in conversations and on Memory Spaces, with a task Agent readiness tag and a receipt in the candidate's language. Mnemon uses DSH's inputs, selectors and dialog buttons, and its dialogs sit on DSH's modal layer. The workspace refresh reloads the open page, Status lists the Providers that run, and the Native Provider is named Mnemon Native.
- **Documentation** ([#307](https://github.com/omdsh-dev/dsh-mnemon/pull/307), [#311](https://github.com/omdsh-dev/dsh-mnemon/pull/311)): a new [installation guide](../guides/installation.md) goes from an empty machine to the first memory on the web, the desktop app or the command line, and the README and guides show interactions recorded with the live model.

## Upgrade and compatibility

Supported hosts are **DSH 0.1.7-rc.2** (npm `latest`) and **DSH 0.2.0-rc.1** (npm `next`). Complete profiles require Node `^22.19.0 || >=24.0.0`; the package's Node import floor remains 20. Older hosts should retain v0.5.16.

Install `dsh-mnemon@0.5.19` through **Plugins → Add plugin**, then choose **Enable now**. The CLI alternative is:

```sh
dsh plugin --profile web add dsh-mnemon@0.5.19
```

Use `headless` for that profile. Include the version for the first 24 hours after publication: pnpm 11 does not pick a version published less than a day ago and would install the previous release, which DSH 0.2 refuses. Afterwards plain `dsh-mnemon` installs 0.5.19. A versioned install pins the version; upgrade it later with `dsh plugin --profile web update --latest dsh-mnemon`. The [installation guide](../guides/installation.md#common-problems) covers these cases.

- **Moving to DSH 0.2:** update dsh-mnemon first, then DSH. If DSH 0.2 starts with an older release, it turns that release off; memory is untouched and returns after the update.
- **Desktop app:** update from the app's Plugins page. No `remoteAccess` change is needed, and a `remoteAccess: trusted-host` override added only as a workaround for #310 can be removed.
- If the running host already loaded an older version, restart DSH once and reload the browser. A fresh installation and **Enable now** need no restart.

No memory storage or configuration migration is required. Plugin authors: the Source-page SDK in `dsh-mnemon/client` adds `SearchField`, `SelectField`, `WriteReceipt`, `TaskAgentTag` and `MemorySourcePageProps.refreshKey`, and the three official Sources that use them now require `dsh-mnemon ^0.5.19`.
