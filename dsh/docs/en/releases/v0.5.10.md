## Runtime and OpenViking writes

Runtime replace and remove prefer a unique exact content match before trying a unique substring. An entry containing only `X` can therefore be edited or removed alongside `EGO_LINUX_CHROME`. Duplicate exact matches still require disambiguation, and refusal leaves existing data intact.

OpenViking creates a unique file containing the original text, verifies indexing and exact content readback, then returns the scoped file identity used by Host receipts and archive compensation. It no longer treats an extraction response as proof that the requested text was stored. Search and browse return full content. Account isolation, legacy owner-root resolution and deletion scope are validated; incomplete or uncertain writes return an error with the candidate URI. The original contributor's commit is preserved in the merged history. Servers lacking the required content write/read contract fail explicitly; no settings or stored content are migrated.

## Automatic review

Automatic review has an independent switch, a default five-minute minimum interval and a limit of 20 attempts per loaded parent Agent. The default spawn path bounds its context; fork remains explicit, with fallback or skip available before child startup. The per-response token limit is not a total usage cap. Attempt budgets reset when the Agent unloads or the Host restarts; existing session history is retained.

With the affected published Agent Teams service and tools enabled together, automatic review pauses before creating a child and explains the incompatible composition. This contains the automatic-review failure; it does not repair upstream Team policy or manual delegation. A failed review can expose receipts for writes it already committed so users can reconcile them without replaying the run.
