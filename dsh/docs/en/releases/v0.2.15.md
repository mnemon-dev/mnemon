# v0.2.15: DSH rc.2 Compatibility and Resilient Task Agents

[简体中文](../../zh-CN/releases/v0.2.15.md) | **English** | [Capability map](../guides/capabilities.md)

v0.2.15 verifies dsh-mnemon against DSH 0.1.1-rc.2, carries multimodal Host content through the existing lifecycle without storing image bytes, and includes the task-Agent and advanced-layout fixes merged since v0.2.14.

## DSH 0.1.1-rc.2 compatibility

- All ten direct `@deepseek-ai/dsh*` development dependencies are pinned to 0.1.1-rc.2. The lockfile matches the official release graph, which intentionally retains rc.1 for unchanged internal packages and contains no older DSH prerelease line.
- The published UI-primitives peer range keeps support for compatible 0.1.0 hosts and the 0.1.1 prerelease line beginning with rc.1, including rc.2.
- The live model catalog now preserves DSH `inputModalities`. Settings labels the first-party `deepseek-official/deepseek-v4-flash-vision-exp` route as **Image input**.
- Lifecycle processing accepts durable DSH image attachment references, preserves all original content blocks when appending guidance, and counts only text toward activity thresholds. Mnemon background metadata, recall, write, distillation, selection, and archive jobs remain text-only.
- DSH rc.2 prioritizes reusable DeepSeek Files API uploads and normalizes image size and format for the selected model. Those uploads remain owned by DSH; dsh-mnemon does not copy raw image bytes into Runtime, Documents, or Memory Spaces.

## Fixed

- A configured background task-Agent model route now reaches every coordinator delegation, including idle review, recall, write, answer, provider placement, migration, USER compaction, document archive, and metadata maintenance.
- Metadata maintenance skips generated candidates whose title or description violates local length bounds. Valid candidates in the same result still apply, omitted spaces retain their existing metadata, and unexpected or duplicate identifiers remain hard failures.
- Sidebar entry discovery and workspace takeover now recognize the DSH advanced-mode frame classes as well as the classic pane layout.

## Safety and upgrade

- No Mnemon persistence format, RPC authority, credential handling, public tool schema, or data migration changes.
- The published package keeps the v0.2 surface: the root plugin, Client wrapper, and package metadata only. No v0.3 kernel, topology, workspace package, or SDK entry is included.
- The published plugin keeps its Node.js `>=20` engine for older compatible DSH hosts. A complete DSH 0.1.1-rc.2 profile requires Node.js `^22.19.0 || >=24.0.0` because the Host uses `Promise.withResolvers` and the Node Zstd API.
- The optional DSH SQLite session backend remains separate from Mnemon storage and uses schema 17. Deployments that selected it manually must follow the upstream backup and recreation requirement; shipped profiles do not select it.
- Upgrade DSH and dsh-mnemon, then restart each affected profile. A package downgrade requires no Mnemon data rollback.

## Verification

- The complete `pnpm run verify` chain passes 380 tests; one Windows-only smoke test is skipped only in the local non-Windows run.
- Deterministic double builds match across 65 generated files. Isolated Headless activation exposes 35 total tools, including all five representative Mnemon tools.
- Package validation reports 72 files. The package keeps only the v0.2 root and Client code entries; publint strict and attw pass.
- Frozen-lockfile installation and the package-version/tag invariant are checked before publication.
- GitHub CI covers Ubuntu on Node.js 22.19 and 24, plus Windows on Node.js 24.
- DSH UI primitives emit only the known development-time missing-source-map warning.
