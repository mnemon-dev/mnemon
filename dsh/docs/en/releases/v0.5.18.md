# v0.5.18: Immediate Activation and Quiet Desktop CLI

[简体中文](../../zh-CN/releases/v0.5.18.md) | **English**

This patch release contains the two fixes merged after v0.5.17:

- **Install and enable without restarting DSH** ([#308](https://github.com/omdsh-dev/dsh-mnemon/pull/308)): Desktop and official WebUI profiles with isolated dependencies can load all default Sources and the Strategy when the bundle was not selected at startup. Mnemon prepares its dependency resolution before starting the native group, then registers Web RPC routes in its own injected scope. The official WebUI can use **Enable now** immediately after installation.
- **Quiet native CLI execution** ([#306](https://github.com/omdsh-dev/dsh-mnemon/pull/306), [#305](https://github.com/omdsh-dev/dsh-mnemon/issues/305)): verified Mnemon npm installations run their native executable directly for memory operations and version checks, avoiding the npm launcher's extra Windows console window. npm retains ownership of updates, and other CLI installations remain supported.

## Upgrade and compatibility

The supported host remains **DSH 0.1.7-rc.2**. Complete profiles require Node `^22.19.0 || >=24.0.0`; the package's Node import floor remains 20. Older hosts should retain v0.5.16.

Install `dsh-mnemon@0.5.18` through the official WebUI's **Add plugin** dialog, then choose **Enable now**. The CLI alternative is:

```sh
dsh plugin --profile web add dsh-mnemon@0.5.18
```

Use `headless` for that profile. If upgrading a version already loaded by the running host, restart DSH once and reload the browser to load the new code. Fresh installation and activation of the new bundle do not require a restart. Updating or removing already-loaded packages remains subject to the host's normal restart requirements.

No memory storage migration is required. Core and component switches retain their existing behavior and saved choices. Keep the new Starter readiness component enabled, and use the bundle or core switch to control the composition. Other loaded plugins retain their dependency routes; DSH source and shared Connection instances are unchanged.

The upstream `cordis:group` display/toggle issue remains documented in [compatibility guidance](../reference/compatibility.md#dsh-017-bundle-component-list). It does not mean that active Sources or Strategies have stopped.
