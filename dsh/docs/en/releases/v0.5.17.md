# v0.5.17: Composable Strategies and Component Settings

[简体中文](../../zh-CN/releases/v0.5.17.md) | **English**

v0.5.17 includes the thirteen PRs merged after v0.5.16. The Starter now pins eighteen packages, including the new General strategy.

- **Strategies and composition** ([#294](https://github.com/omdsh-dev/dsh-mnemon/pull/294), [#299](https://github.com/omdsh-dev/dsh-mnemon/pull/299), [#301](https://github.com/omdsh-dev/dsh-mnemon/pull/301)): choose Layered or General strategy under Plugins, compose Sources and enhancements from their declarations, and keep dependent switches in step. General admits available Sources and lets the model choose how to use them. Standard selection, projection and capture enhancements can follow either strategy. A conversation can continue without memory when no main strategy runs.
- **Component settings and interface** ([#297](https://github.com/omdsh-dev/dsh-mnemon/pull/297), [#298](https://github.com/omdsh-dev/dsh-mnemon/pull/298), [#300](https://github.com/omdsh-dev/dsh-mnemon/pull/300), [#302](https://github.com/omdsh-dev/dsh-mnemon/pull/302)): configure Mnemon on its DSH Plugins page. Each component owns its settings and can contribute a Status card. Switches and selectors apply immediately; typed values use Apply. Storage offers explicit Default and Custom directory choices. The UI follows DSH primitives and theme tokens.
- **Optional CLI and peer Providers** ([#295](https://github.com/omdsh-dev/dsh-mnemon/pull/295)): only Mnemon Native needs the Mnemon CLI. Other ready Providers can serve Memory Spaces when Native is unavailable; saved Provider choices remain honored.
- **Naming and navigation** ([#290](https://github.com/omdsh-dev/dsh-mnemon/pull/290), [#292](https://github.com/omdsh-dev/dsh-mnemon/pull/292), [#303](https://github.com/omdsh-dev/dsh-mnemon/pull/303)): retain “可组合记忆 (dsh-mnemon)”, describe layered memory as the default composition, and use a thin brain outline for memory navigation. Local credentials and tool state are excluded from Git.
- **Host compatibility and documentation** ([#293](https://github.com/omdsh-dev/dsh-mnemon/pull/293), [#291](https://github.com/omdsh-dev/dsh-mnemon/pull/291)): target published DSH 0.1.7-rc.2 contracts, remove older-host compatibility paths, and document the upstream `cordis:group` display issue.

- **General read receipts**: release acceptance caught a DSH tool-output rejection when Source evidence omitted optional `score` or `revision`. The Host now preserves omission for `mnemon_recall` and `mnemon_related`, while retaining zero scores and supplied revisions.

## Upgrade and compatibility

**This release supports DSH 0.1.7-rc.2. Keep v0.5.16 on older hosts.** Complete profiles require Node `^22.19.0 || >=24.0.0`; the package's Node import floor remains 20.

Back up the Profile configuration and memory data, then install the complete Starter:

```sh
dsh plugin --profile web add dsh-mnemon@0.5.17
```

Restart DSH and reload the browser; substitute `headless` for that Profile. Mnemon CLI has its own release cycle and is needed only for Mnemon Native.

Memory storage formats are unchanged. Previously saved component choices move into the DSH Profile patch when its plugin manager is available. A data-directory change does not move existing memory; copy or restore data explicitly when changing location. Preserve the Profile backup for rollback as well as the data backup.

The five Strategy packages now require `dsh-mnemon ^0.5.17`, because they use the new standard View extension SDK. Upgrade the pinned combination together; independent plugin installations must satisfy that peer floor.

DSH 0.1.7-rc.2 can still show the `cordis:group` container as Off while its children run; clicking that container can return `unknown-plugin`. The release does not patch DSH. See [compatibility guidance](../reference/compatibility.md#dsh-017-bundle-component-list) and [upstream issue #649](https://github.com/dsh-external/issues/issues/649).
