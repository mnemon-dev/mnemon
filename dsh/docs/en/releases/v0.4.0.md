# v0.4.0: Sidebar-only Memory System

[简体中文](../../zh-CN/releases/v0.4.0.md) | **English** | [Capability map](../guides/capabilities.md)

v0.4.0 makes Sidebar the only Memory System workspace. It removes the builtin presentation and display-mode setting while retaining the v0.3 architecture and memory formats. The complete view-based upgrade is planned separately for v0.5 and is not included in this release.

## Main changes

- **One workspace entry.** Memory System opens only from the DSH sidebar; the plugin no longer registers a `conversation.view` tab. Existing Sidebar pages, navigation, dialogs, and workspace selection remain available. [#128](https://github.com/omdsh-dev/dsh-mnemon/pull/128)
- **No display-mode selector.** Remove the presentation setting, its bilingual copy, and the builtin-only appearance, navigation, inline-editing, and styling branches. The minimal Sidebar presentation is now unconditional.
- **Live visibility remains independent.** `tabEnabled=false` hides the Sidebar entry and workspace live; enabling it restores Sidebar. Host RPC, commands, and Agent tools stay registered. Turn memory and Save to memory remain controlled independently by `mnemon-ui`.
- **Keep the v0.3.6 fixes.** Async Recall delegation, per-turn budgets, Runtime Memory snapshot ownership, panel navigation, CLI discovery, and host-aligned dialog surfaces remain intact. This release does not introduce the new view-based core, SDK, or standalone-plugin architecture.

## Upgrade and compatibility

This is an intentional presentation and configuration compatibility change, not a data-format migration.

1. **Builtin users move to Sidebar.** The legacy value is spelled `buildin` in saved configuration. Existing YAML and user settings containing `displayMode`, including that value, still load; the field is ignored and the workspace uses Sidebar. Manual cleanup is optional, and no saved configuration file is automatically rewritten.
2. **Update typed integrations and settings writers.** `Config.displayMode` and `ResolvedConfig.displayMode` are removed. New settings RPC mutations that include `displayMode` are rejected. Remove the field from configuration objects and update payloads rather than relying on legacy read compatibility.
3. **Memory data is retained.** Runtime, Documents, Memory Space registries, Provider data, storage paths, credentials, and authority boundaries are unchanged. No memory data is migrated or deleted.
4. **Choose the minor-version upgrade explicitly.** Install `dsh-mnemon@0.4.0` in the owning DSH profile, then restart profiles using it and reopen Memory System. A dependency constrained to `^0.3.x` does not automatically select v0.4.0. Back up settings and data before upgrading.

The published DSH baseline remains 0.1.1-rc.2. DSH 0.1.2-alpha.1 remains a source-only compatibility target, not an npm installation target.

## Rollback

Reinstall `dsh-mnemon@0.3.6` in the same profile and restart it. No data conversion is needed. A retained legacy `displayMode: buildin` preference becomes effective again on the older version; remove it or select Sidebar there if that is not desired.

Package-content checks covered 114 files; all 10 Node-compatible public entry imports, publint strict, and the attw ESM profile passed.

Sidebar open/return/reopen, the selector-free settings page, Runtime dialog, and 680px layout with Escape dismissal passed without browser console errors. This UI-only fixture used synthetic data and an intentionally unavailable native CLI; no native-Mnemon end-to-end or real-model result is claimed.
