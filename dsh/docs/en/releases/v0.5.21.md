# v0.5.21: Large Native Spaces and Leaner Hot Memory

[简体中文](../../zh-CN/releases/v0.5.21.md) | **English**

This patch release contains the three pull requests merged after v0.5.20:

- **Large Native spaces work again** ([#321](https://github.com/omdsh-dev/dsh-mnemon/pull/321), issue [#320](https://github.com/omdsh-dev/dsh-mnemon/issues/320)).
  - Mnemon Native reads a whole Memory Space in three places: its contents list, its graph, and the exact-content check that runs before runtime memory archives entries at capacity. Every Mnemon command stopped at 2 MiB of output, but a space of about 1,000 insights returns 3–9 MB.
  - On a 900-insight space the contents list read 0 memories and the graph "connection unavailable". Adding working memory at capacity failed with a hint to install Mnemon, so working memory could no longer make room.
  - Those whole-space reads now accept up to 128 MiB, and every other command keeps 2 MiB. A failure names its cause: only a failed launch suggests installing Mnemon.
- **Idle review writes one layer** ([#322](https://github.com/omdsh-dev/dsh-mnemon/pull/322), issue [#319](https://github.com/omdsh-dev/dsh-mnemon/issues/319)).
  - Idle review, the only unattended writer, sent stable project facts and decisions to MEMORY.md, which every turn loads. One pass could record the same knowledge as a Document and again as a working-memory entry.
  - Review now considers a Document first. MEMORY.md takes only a compact rule the user stated, such as a convention, a correction, an environment fact or a tool quirk, that no Document or entry already covers; project records such as designs, implementation details, paths and ports never go there.
  - The review guard holds each pass to one layer: after a Document, working-memory changes are refused, and after a working-memory change, a Document is refused. USER.md changes stay independent.
  - A new **Write runtime memory** switch under **Idle review** on the Layered strategy's page (`idleReview.runtimeMemory`, on by default) limits review to Documents.
- **The fallback sidebar entry matches DSH's rows** ([#323](https://github.com/omdsh-dev/dsh-mnemon/pull/323), issue [#318](https://github.com/omdsh-dev/dsh-mnemon/issues/318)).
  - In layouts without DSH's native panel seat, Mnemon inserts its own Memory System entry, which kept an older style. Next to DSH's rows it looked smaller, greyer and 8px indented.
  - It now copies DSH's panel row: inherited 14px text in the primary color, the same padding, margins and corners, a 16px icon (18px collapsed), and DSH's highlight. The open entry is also `aria-current="page"`. Layouts with the native seat are unchanged.

## Upgrade and compatibility

Supported hosts: **DSH 0.2.0-rc.2** (npm `latest` and `next`) and **DSH 0.1.7-rc.2**. Complete profiles require Node `^22.19.0 || >=24.0.0`. Older hosts should retain v0.5.16.

Install `dsh-mnemon@0.5.21` through **Plugins → Add plugin**, then choose **Enable now**. The CLI alternative is:

```sh
dsh plugin --profile web add dsh-mnemon@0.5.21
```

Include the version for the first 24 hours after publication. pnpm 11 does not pick a version published less than a day ago, so until then a plain install or update picks 0.5.20, which both hosts accept. A versioned install pins the version; upgrade it later with `dsh plugin --profile web update --latest dsh-mnemon`.

- **Existing installations:** for the first 24 hours run `dsh plugin --profile web add dsh-mnemon@0.5.21`. Afterwards `dsh plugin --profile web update dsh-mnemon` works (`update --latest` for a versioned install). Then restart DSH. Desktop users update from the app's Plugins page and then quit and reopen the app.
- **Idle review:** existing profiles keep runtime memory writes under the new rules; turn off **Write runtime memory** to keep review to Documents. Entries that review wrote before this release stay in MEMORY.md until you remove them.
- **Large spaces:** the new cap needs the new Memory Spaces Source and Mnemon Native together, which the Starter pins. Mnemon Native 0.5.8 on an older Memory Spaces host keeps the 2 MiB cap.

No memory storage or configuration migration is required.
