## 复现与测量方法

基线为 `d13d9c1ab118e01926c0e60fbf273de8457872df`（main，v0.5.22）。优化版源码 revision 与汇总指标见 [metrics.json](./metrics.json)。两份独立 checkout 使用完全相同的基准源码与冻结依赖锁文件，在同一机器顺序运行。原开发工作区没有改动。

```sh
pnpm install --frozen-lockfile
MNEMON_BENCH_OUTPUT=/tmp/algorithm-benchmark.json pnpm bench:algorithms
# 仅测试要求的三个小规模
MNEMON_BENCH_SIZES=1,10,100 pnpm bench:algorithms
```

复现旧版时，将 `tests/algorithm-performance.measure.ts` 与 `scripts/benchmark-algorithms.config.ts` 复制到该基线 revision 的临时 checkout，再执行 `pnpm exec vitest run --config scripts/benchmark-algorithms.config.ts`。旧版没有新增的 package script。

脚本在临时目录生成合成数据，结束后清理，不使用生产数据、付费 API、LLM、真实网络或外部 CLI。每项先预热三次，再取九组样本；N=1/10/100 每组平均十次操作，N=1000 每组平均三次（成本较高的 pinned-recall 与 batch-prepare 每组一次）。样本之间让出事件循环，等待不计入耗时。准备/恢复数据、安装依赖和断言在计时外，完整本地方法调用（含其文件 I/O）在计时内。报告中的 median/p95 是**样本均值的分位数**，不是单次请求的 p95。OS 文件缓存已预热，没有强制 GC；这是单进程延迟测试，不是并发吞吐测试。

各项 N 含义分别为：

- Runtime：N 条已提交记忆加一条哨兵；压缩时移除哨兵，按混合优先级装填 N 条候选。测试容量为每个目标 1 MiB。
- Documents：N 份约 4 KiB 的正文，返回上限 10，测试容量 16 MiB。搜索包含正常的最近访问时间持久化，catalog 包含文件健康检查。
- Holographic：N 条 JSON 事实，固定信任分数生成规则和查询；search 返回 10 条，related 返回 20 条。写入包含全量 JSON 序列化和原子替换。
- Provider 发现：N 个命名空间；Native catalog：N 个真实目录和合成数据库标记文件。Provider 发现使用内存 registry，以隔离匹配成本和持久化成本。
- 多路召回：N 个活跃空间，每路固定 30 条候选，最终上限 10，使用同一种标准化分数 Provider。`pinned` 显式指定全部空间。运行真实 service/registry，adapter 返回本地夹具，因此衡量编排成本，不衡量远程延迟或召回质量。
- 批量准备：N 空间目录中向一个目标提交 N 条请求，adapter 返回有序合成回执。`batch-grouping` 仅把 `get()` 替换为常量夹具，分离分组与目录投影成本。这两项不包含 Provider 持久化或 checkpoint 落盘。
- Core：真实三 Source 组合中放入 N 条短 Runtime 记忆；Source 数量始终是三，是对照项，不代表 N 个 Source 的扩展性。

N=1/10/100 容易受固定开销影响，因此补充 N=1000 和确定性的工作量计数。耗时本身不能证明 Big-O；下面的复杂度来自代码循环与数据结构分析。

## 复杂度与处理决策

符号：N 为记录数，B 为全部文本/序列化字节数，Q 为查询 token 数，M 为匹配候选数，k 为返回条数，S 为配置空间数，P 为本次请求空间数，C 为全部召回候选数，W 为批量写入数，U 为不同写入目标数。Map/Set 查找采用期望/摊还复杂度；字符串散列、文件系统与 Provider 成本另外计入。元数据字段、分支数量及多数输出上限有配置边界。

| 路径 | 优化前 | 优化后 | 原因与保留语义 |
|---|---|---|---|
| Runtime 压缩 | 平均文本长度 L 时 O(N²L)，另加 JSON I/O | O(N+B) | 原内容建立一次索引并保留首个匹配；三个稳定优先级桶，增量计算 UTF-8 与分隔符字节。最终仍按输入顺序返回保留条目。 |
| Runtime 快照、投影、增改删 | 每次 O(N+B) | 同阶 | 保留完整 JSON 校验、精确匹配、投影修复、容量检查与提交标记。对持续增长的存储执行 N 次单条写入，累计仍为 O(N²)。 |
| Document 搜索 | O(QB+M log M)，另加 index I/O；所有可搜索正文都生成摘要 | 主复杂度同阶，摘要处理只作用于返回正文 | 保留实时正文读取、子串评分、token 覆盖、分数/日期稳定排序、allowed IDs 与最近访问时间写入，不引入可能过期的文本索引。 |
| Document 元数据、读取、写入 | Catalog 为 O(N) 元数据与 stat；get 为 O(N+目标正文字节)；写入含 index、正文、N 次 stat 与未缓存摘要；归档候选排序 O(N log N) | 同阶 | 保留磁盘身份缓存、锁、revision、完整 index 持久化和有界摘要缓存。 |
| Provider 空间发现匹配 | D 个发现项匹配 S 条现有记录：O(SD) | O(S+D) | 请求内索引保留原 ID、人工/AI 元数据、激活状态、时间戳与首个匹配语义；字段规范化和 registry 序列化仍需处理各自字节。 |
| Native 目录发现 | D 个目录与 S 个 ID 比较：O(DS) | O(S+D) | 每次仍枚举目录并检查数据库存在，只在当次扫描中使用 Set。 |
| 固定范围空间解析 | 重复 P 次目录投影：O(PS)，未计旧版目录嵌套扫描 | 一次目录加 P 次查找：O(S+P) | 保留 ID 校验、活跃/启用检查、去重与请求顺序，每次操作重新读取。 |
| 多路排名与质量统计 | O(C log C+PC) | O(C log C+C+P) | 一次汇总全部 evaluated/selected，取代按空间反复过滤。融合排名、每个计数器、降级策略、故障状态和传入策略的所有候选不变。遵守上限的 adapter 通常满足 C≤50P。 |
| 批量写入分组与准备 | O(W²) 数组复制/成员检查，加 W 次目标投影 | O(W) 分组，加 U 次目标解析 | 保留全部写入前的同步校验、目标顺序、Native 长条目单写回退、回执顺序、部分失败和逐目标激活。准备仍含 O(U(S+D)) 目录成本，成功持久化另计 Provider I/O。 |
| Holographic token 重叠 | 集合大小 a、b 时 O(a+b)，并分配临时并集 | O(min(a,b)) 成员检查、常量辅助空间 | 使用精确 Jaccard 并集大小 a+b−交集；分词仍与文本长度有关。 |
| Holographic search/related 排名 | 全排序 O(M log M) | O(M log k+k log k)，排名辅助空间 O(k) | 堆顶保存当前最差入选项，最后稳定排序。小集合仍用原生 sort；旧数据出现非有限分数时保留旧全排序，因此该兼容分支仍为 O(M log M)。候选集合和 JSON 解析仍占 O(N+B) 空间。 |
| Holographic list/graph/status/write | 全量读写 O(N+B)；list 排序 O(N log N)；实体汇总另加 O(E log E) 排序 | 同阶 | 保留每次读文件、精确去重、时间戳、文件模式、图身份和全量持久化；search/related 优化没有把 JSON 变成索引数据库。 |
| Core 与 Strategy | Source facts/project 并发；JSON 处理遍历字节、排序对象键；另计策略选择成本 | 保留 | 保留确定性重放、不可变 View、digest、预算、授权、超时和取消。默认 Layered 使用三个角色；自定义策略有各自复杂度。一些声明/扩展成员检查对较小的有界列表仍为平方级。 |
| 图谱、列表、实体联邦查询 | 图投影 O(V+E)；列表过滤与返回字节有关；实体汇总 O(E+H log H)，H 为不同实体数；另加空间解析/Provider | 数据处理同阶，固定范围空间解析改善 | 保留全部边、命名空间 ID、顺序、total、分来源诊断与过滤。 |
| Native CLI adapter | 返回规范化 O(响应字节)；精确批量归档通过 Map 为 O(已有+请求字节) | 保留 | SQLite/向量/图内部搜索属于外部 Mnemon 版本。保留只读检查、精确导入确认、输出上限和进程序列化。 |
| 远程 Provider adapter | 本地解析 O(响应字节)，网络/服务算法在外部 | 保留 | Honcho、Mem0、Hindsight、RetainDB、ByteRover、Supermemory 的服务端算法不在本仓库。OpenViking 额外并发读取最多 k 条正文；Hindsight related 逐层扫边 O(depth·E+V)，service 将 depth 限为五。 |
| Pack 导入导出 | 校验、散列、复制与 payload 字节有关，另加文件名排序 | 保留 | 事务 staging、校验和、权限检查和回滚是正确性工作；没有更改格式或迁移方式。 |

联邦召回保留完整全局候选排序，因为自定义质量策略接收完整有序数组、可以任意选择；提前截断会改变结果。完整 JSON 持久化和任意子串匹配的成本也不能靠换一个循环变为常数。持久索引、跨请求陈旧缓存、近似向量替代、取消策略和并发上限变更需要独立的兼容性/质量证据。

## 兼容性与验证

- 使用 CI 工具版本 Node 22.19.0 + pnpm 10.13.1 完整通过 `pnpm run verify`：独立插件 452 项、Root/Host/Core/UI 1611 项测试通过；插件 3 项、根目录 6 项可选测试跳过。包含文档/类型检查、确定性双构建、全部独立构建、真实隔离 Headless 激活、包内容/公共入口、publint 与 attw。
- `pnpm run release:intent` 确认根包与四个修改的插件均有 changeset。
- 前后顺序基准均通过，各 68 个规模/项目组合。[metrics.json](./metrics.json) 保存源码 revision、负载参数、中位数/p95 样本均值、工作量计数和一致的基准文件 SHA-256。
- 新增压缩/service 回归在基线恰有五项预期失败（线性字节工作量、两种规模的统计访问量、固定范围目录次数、目标解析次数），优化版 12 项全部通过。其他排名、Document/Holographic 回归也通过。
- `pnpm run verify:plugins` 通过：17 个独立插件仓库、18 个发布包、无 workspace 链接、外部公共 SDK/Client 使用方的类型/构建/测试、真实 DSH packed Starter 安装激活，以及三个可选打包 Strategy 插件同时启用。

首次使用系统工具验证时发现两个既有环境问题：pnpm 11.25 拒绝仓库有意存在的 workspace 任务环；本机 Node 25.1.0 的旧 Native CLI 符号链接删除夹具失败，未修改 main 也有同样错误。该 CLI 文件的九项测试在 Node 22.19.0 全部通过，完整验证使用 CI 的这个版本，没有为这些环境问题修改源码或测试。两版性能基准均使用相同的 Node 25.1.0 环境，与之后的兼容性验证分开记录。

跳过项需要真实 Native/OpenViking/Flash 服务或 Windows 集成环境；本地测试不替代这些真实集成。Windows 与 Node 20/24 由 GitHub CI 验证。

定向回归覆盖 UTF-8 精确边界（含补充平面字符和孤立代理项）、优先级、稳定同分排序、空/满预算、时间戳与分支继承、历史重复内容、Document 外部修改和文件丢失、读取范围、停用/未知空间、全部质量计数器、Provider 故障、有序批量回执与副作用前校验。堆排名与原稳定全排序比较升序、降序、同分、混合和非有限分数。

确定性工作量测试把 Runtime 被计数字符限制在线性输入规模内，把召回统计访问次数限制为 C+k，不依赖 CPU 速度。将这些测试复制到基线运行，验证旧平方级路径确实违反上界。

没有更改 schema、配置、文案/UI 流程、RPC DTO、依赖版本、外部请求 payload、持久缓存、模型策略或付费服务配置。已有数据不需要迁移，回滚仍兼容。上述证据只覆盖已测工作负载与契约，不是对所有生产环境绝无故障的保证，也不预测 LLM/网络端到端延迟。
