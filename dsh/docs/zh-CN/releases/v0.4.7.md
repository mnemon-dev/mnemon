# v0.4.7：DSH 0.1.2-rc.1 兼容

**简体中文** | [English](../../en/releases/v0.4.7.md)

v0.4.7 将已发布的 DSH 0.1.2-rc.1 提升为 dsh-mnemon 稳定的 registry 与开发基线，同时保留对其直接前序 DSH 0.1.2-alpha.5 tag 的完整源码验证，以及 DSH 0.1.1-rc.2 上的真实 WebUI 向后回归。[PR #161](https://github.com/omdsh-dev/dsh-mnemon/pull/161)、[PR #162](https://github.com/omdsh-dev/dsh-mnemon/pull/162)。

## 兼容性变更

- 直接使用的 22 个 DSH 开发依赖全部精确固定到 `0.1.2-rc.1`。显式加入 Store 与 Invariants，闭合已发布的类型和 peer 依赖图，不再依赖传递安装的偶然结果。
- 子 Agent token selector 改从公开 owner `@deepseek-ai/dsh-client-store` 导入 `SnapshotSelectorHook`，UI Slots package 继续提供 `StoredEntry`。这只是类型边界修正，不改变运行时 token 统计。
- Lockfile 只包含一套一致的 rc.1 预发布依赖群。pnpm 11 release-age 豁免只精确枚举 lockfile 中实际存在的 rc.1 package，后续发布的 `@deepseek-ai` package 仍会继续隔离。
- DSH 0.1.2-alpha.5 继续由源码覆盖 job 验证，并包含 Store 与 Invariants。基于能力的 Session 读取继续同时支持 alpha.5/rc.1 的 snapshot 接口与 rc.2 的 `events[]` 属性，不解析 package 版本。

## 云端 WebUI 认证

当前部署指南已切换到 DSH 0.1.2-rc.1 transport：页面、每个 RPC 与每条 stream 都使用 Host 启动 token URL 和签名、绑定 authority 的 Cookie 所建立的浏览器会话。`--trusted-host` 仍只是 Host/Origin 防线；公网入口仍需 HTTPS 与部署层访问控制。

上一条 DSH 0.1.1-rc.2 流程作为显式回滚路径保留。它的逐方法 authority 层仍要求启动时 Mnemon `remoteAccess: trusted-host` 覆盖，才能从远端使用设置、备份、Provider 连接和宽泛 mutation 通道。DSH 0.1.2-rc.1 与 alpha.5 会忽略这一保留的兼容设置。

## 升级与兼容性

安装稳定版 DSH 0.1.2-rc.1，在每个所属 profile 中安装 `dsh-mnemon@0.4.7`，然后重启这些 profile：

```sh
npm install -g @deepseek-ai/dsh@0.1.2-rc.1
dsh plugin --profile web add dsh-mnemon@0.4.7
dsh plugin --profile headless add dsh-mnemon@0.4.7
```

DSH 各 profile 的插件清单彼此独立，只需执行适用于当前安装的 profile 命令。记忆数据、存储路径、Pack 格式、Provider 凭据、运行时默认配置、生产依赖、公开 package exports 与 Session 投影状态均不变，无需迁移或删除缓存。

## 验证

实现与发布候选在 Node 24.18.0 与 pnpm 10.13.1 下通过完整 `pnpm run verify`：654 项测试通过，1 项 Windows 专用测试在 macOS 跳过。110 个构建文件的确定性检查、隔离 Headless 激活、10 个 Node-compatible 公开入口、117 文件发布包内容检查（383,848 packed bytes；1,707,083 unpacked bytes）、publint 与 attw 均通过。

PR #162 的 Linux Node 22.19/24、Windows Node 24、源码链接 DSH 0.1.2-alpha.5 与双语贡献规范 job 全部通过。其 pnpm 11.7 registry 安装按精确 release-age 豁免集合检查了 936 个依赖条目。

隔离的 DSH 0.1.2-rc.1 WebUI profile 完成状态加载、记忆系统导航、合成对话、只读保存弹窗与刷新持久化；另一套 DSH 0.1.1-rc.2 profile 完成同一对话与刷新回归。浏览器 warning/error 日志与对应 Host 诊断均为空。截图显示插件版本 0.4.6，是因为它们记录的是本次仅改版本号的发布准备之前、实际可执行的兼容实现 commit；之后没有修改运行时源码。详见[环境记录与截图](../../pr-assets/dsh-rc1-compat/README.md)。

## 回滚

在相同 profile 中重新安装 `dsh-mnemon@0.4.6` 并重启，无需转换数据。v0.4.6 发布时尚未以 DSH 0.1.2-rc.1 为基线；如果需要完整经过验证的回滚，也应把 DSH 恢复到原 0.1.1-rc.2 基线。远程暴露该 profile 时，请使用 rc.2 专用的云端步骤。
