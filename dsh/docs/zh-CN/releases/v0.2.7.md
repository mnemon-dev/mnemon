# v0.2.7：隔离的子 Agent 结果通道

**简体中文** | [English](../../en/releases/v0.2.7.md) | [能力地图](../guides/capabilities.md)

v0.2.7 在保持严格子 Agent 工具隔离的前提下，恢复 DSH 0.1.0-rc.6 上的监督式记忆操作。

## 修复

- 每次 Mnemon 委派运行都会注册一个名称唯一的继承结果工具，其参数严格匹配当前操作的结果 schema。
- 该次运行专属的结果工具会显式加入现有 `toolFilter`；召回、写入、审查、Provider 选择、迁移、压缩、档案归档和元数据任务继续保留原有硬工具 allowlist。
- 父级会校验结果 schema 和子 Agent 身份，拒绝重复或缺失的完成调用，处理嵌套 code-mode 完成，并在运行结束后注销工具和事件监听器。
- 该实现不再依赖 DSH 延迟注入的 `structured_output` 路径；后者在子 Agent 工具过滤后可能不可达，并导致 `memory subagent stopped with error`。

## 兼容性

- 修复完全位于 dsh-mnemon 内部，不要求修改 DSH。
- 公共工具契约、存储布局、记忆空间 schema、Provider 配置和持久化数据均未改变。
- 问题影响共享的委派结果通道，因此本次修复覆盖全部监督式 Mnemon 操作，而不只限于 `mnemon_recall` 和 `mnemon_remember`。

## 验证

- 完整测试套件 334 项通过；Windows 专用 smoke test 只会在非 Windows 本地环境跳过。
- 确定性构建、Headless 激活、包检查以及 Ubuntu、Windows CI 均通过。
- 真实 WebUI 覆盖 Agent Query 与对话内 `mnemon_recall`：子 Agent 只调用获准的读取工具，随后调用唯一结果工具，并将经过校验的结构化结果返回父 Agent。

## 升级

更新 dsh-mnemon 后重启对应 DSH profile，无需迁移数据。

上一个补丁版本见 [v0.2.6 发布说明](./v0.2.6.md)。
