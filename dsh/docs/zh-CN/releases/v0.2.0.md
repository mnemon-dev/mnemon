# v0.2.0：可插拔的三层记忆系统

**简体中文** | [English](../../en/releases/v0.2.0.md) | [能力地图](../guides/capabilities.md)

v0.2.0 将 dsh-mnemon 从 Mnemon 工作台升级为长期记忆 Provider 控制面。运行时记忆和项目档案仍由 dsh-mnemon 可靠管理；第三层记忆空间现在可以在 Mnemon、OpenViking、Honcho、Mem0、Hindsight、Holographic、RetainDB、ByteRover 与 Supermemory 之间选择。

## 本次升级

- 九种 Provider 进入同一套服务配置、记忆空间实例、激活、检索、内容、实体、沉淀和状态观察工作流；
- Provider 默认关闭，设置页只管理服务，记忆空间页管理实例；
- 支持人工指定与规则 + Prompt 驱动的智能 Provider 选择；
- AI 元信息、Agent 查询、沉淀记忆和档案归档使用无会话历史的独立顶层任务 Agent；
- 后台任务 Agent 可以跟随 DSH 新会话模型，也可以单独指定 Provider 与模型；
- 记忆空间首次进入时全量同步，之后按记忆空间按需重连，不再每 15 秒阻塞轮询；
- 状态、记忆空间、内容和检索采用并发、渐进式加载，局部失败不再阻塞整页；
- Sidebar 默认一级顺序统一为**状态、运行时、档案、记忆空间**；
- 全局、工作区与自定义范围扩展到支持该语义的本地 Provider，同时保留远程 Provider 自己的命名空间；
- 对话内“本回合记忆”和“存入记忆”继续复用原有用户心智，并能精确跳转到新的多 Provider 页面。

## 从 0.1.x 升级

1. 备份当前 Mnemon 根目录或通过设置页导出 Mnemon Pack；
2. 更新 dsh-mnemon 并重启对应 DSH profile；
3. 打开**设置 → 记忆系统**，确认展示形态、存储位置和后台任务 Agent 模型路由；
4. 需要三方 Provider 时逐个启用并保存服务配置；它们默认保持关闭；
5. 打开**记忆空间 → 概览**完成首次发现与同步，检查每个实例的作用域和激活状态；
6. 用原始检索和 Agent 查询各验证一次，再进行写入或迁移。

升级不会自动迁移、合并或删除 `~/.mnemon`、工作区 `.mnemon`、自定义根或远程 Provider 数据。关闭三方 Provider 只清理 dsh-mnemon 的本地目录元数据；重新连接会从 Provider 重建。

## 推荐基线

- Node.js 20 或更新版本；
- DeepSeek Harness 0.1.0-rc.6；
- 使用 Mnemon Native 时推荐 Mnemon 0.2.3 或更新版本。
