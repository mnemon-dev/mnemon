# v0.5.24：完整的实体计数与按需查找的相关记忆

**简体中文** | [English](../../en/releases/v0.5.24.md)

本补丁版本发布 [PR #332](https://github.com/omdsh-dev/dsh-mnemon/pull/332)。在**记忆系统 → 记忆空间 → 实体**中，实体旁的数字与选中后列出的内容对不上：计数 22 的实体可能只列出 5 条，计数 5 的实体却可能列出 9 条。

- **计数来自全部记忆。** 实体列表把 Provider 状态中每个空间出现最多的 20 个实体相加，多数实体因此缺失，部分计数偏少。现在每个空间用 Provider 列出的记忆建立一份实体索引：实体的计数就是带有它的记忆数，列表包含全部实体。不同写法按概览图谱的方式合并，两处因此一致。
- **选中后正好列出这些记忆。** 选中实体时走的是给 Agent 用的召回，其质量策略最多保留四条中相关结果，空出的名额被不带该实体的记忆补上。现在选中后立即列出带有该实体的全部记忆，按重要性排序，分页显示。
- **相关记忆按需查找。** 列表下方的**查找相关记忆**会在不带该实体的记忆中召回与它相关的那些。召回每个空间约需半秒，因此只在需要时运行。展开后，在本次浏览器会话中切换到其他实体时保持展开，直到收起为止。输入的名称没有任何记忆带有时，相关记忆会自动显示。
- **加载更平稳。** 各空间在索引读取完成前先行显示；读取耗时较长时才显示占位；对较早选择的迟到响应会被丢弃；删除的记忆立即从列表中移除。
- **Provider。** `list()` 取不全整个空间的 Provider，可以实现可选的 `entityIndex(body)`，见[扩展开发](../development/extensions.md)。第一方 Provider 无需改动。

## 实测

合成的 Mnemon Native 空间，在 DSH 0.2.0-rc.2 与 0.1.7-rc.2 的 WebUI 中：

| | v0.5.23 | v0.5.24 |
| --- | --- | --- |
| 列出的实体 | 63 个中的 52 个 | 63 个全部 |
| `Atlas`：计数 / 列出的记忆 | 22 / 20，其中 3 条不带该实体 | 22 / 22 |
| `WebUI`：计数 / 列出的记忆 | 3 / 8 | 4 / 4 |
| 点击后第一条记忆出现 | 400–1,891 毫秒 | 91–99 毫秒 |

在四个各 500 条记忆的空间上，选中实体原先在 1.5–1.7 秒后显示 20 条结果；现在 7–10 毫秒后显示带有该实体的全部记忆（各次运行中为 855、211 与 86 条），需要时查找相关记忆用时 1.5–1.8 秒。全部运行结果，包括报告所用导出数据的副本，见[实体页记录](../../pr-assets/entities-complete-index/README.zh-CN.md)。

## 升级与兼容性

从 v0.5.22 可使用**记忆系统 → 状态 → 检查版本 → 更新**，完成后重启 DSH。命令行安装或更新到精确版本：

```sh
dsh plugin --profile web add dsh-mnemon@0.5.24
```

安装后重启正在运行的 DSH；新安装可在插件页选择**立即启用**。明确指定版本可避免 pnpm 发布后 24 小时的等待窗口选中较早的版本。较早的桌面安装升级方式见[兼容性与升级](../reference/compatibility.md)。

支持的宿主仍为 **DSH 0.2.0-rc.2**（npm `latest` 与 `next`）和 **DSH 0.1.7-rc.2**；完整 Profile 使用 Node `^22.19.0 || >=24.0.0`。存储格式与配置不变，无需迁移已有记忆。实体索引保存在内存中，空间变化后重新建立。不新增 Starter SDK 导出，插件 peer 下限不变。
