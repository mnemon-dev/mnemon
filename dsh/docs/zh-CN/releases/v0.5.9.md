# v0.5.9：运行时归档目标与旧会话恢复

**简体中文** | [English](../../en/releases/v0.5.9.md)

v0.5.9 包含 [#252](https://github.com/omdsh-dev/dsh-mnemon/pull/252) 的运行时归档目标修复、[#253](https://github.com/omdsh-dev/dsh-mnemon/pull/253) 的旧会话恢复，以及此前已合并的 [#249](https://github.com/omdsh-dev/dsh-mnemon/pull/249) 侧栏文字对齐修复。

## 运行时归档

触发容量维护的写入，现在可以归档到发起 View 在召回固定后启用或创建的合格空间。Host 向拥有该空间的 Memory Spaces Source 查询写入范围，并在每批写入前重新检查准确的 Source、View、活跃目标与取消状态。召回范围仍然固定，旧 Source 保留保守回退。拒绝操作时保留已有 Runtime 条目与待写入内容。

## 旧会话恢复

显式副本修复 CLI 支持三个已知旧 Mnemon summary、兼容的 v2 子 Agent descriptor、packed 空字符串占位值和 null delta name。它保留流组装、序号与 provenance、token 时序，以及其他插件的内容。

对于被旧 DeepSeek 适配器清空 ID 的完整工具链，修复只能恢复同一条流中已经记录的唯一 provider ID，并要求调用与结果正文一致、所有归属引用闭合。不会生成新 ID。缺少候选、身份冲突或引用无法确认时，仍拒绝输出整个副本。原文件与已有输出路径不会被覆盖。预览及写入新副本的命令见[运维指南](../guides/operations.md)。

尚未取得报告者原始的 Windows source-build 日志进行直接验证，因此 [Issue #251](https://github.com/omdsh-dev/dsh-mnemon/issues/251) 保持开启，等待这些文件的恢复确认。

## 发布包与升级

- `dsh-mnemon`：**0.5.9**。
- `dsh-mnemon-source-memory-spaces`：**0.5.7**。

Starter 精确固定完整的十六插件组合，其余十五个插件版本与支持的 DSH peer 范围保持不变。Mnemon CLI 独立维护。

```sh
dsh plugin --profile web add dsh-mnemon@0.5.9
```

重启 DSH 并刷新浏览器；Headless Profile 将命令中的 `web` 替换为 `headless`。完整 DSH Profile 需要 Node `^22.19.0 || >=24.0.0`。升级包不会自动改写旧会话文件，需要时使用显式修复命令。

## 验证

整合实现通过 1,452 项测试，6 项 opt-in 跳过，并完成真实 Mnemon 0.2.8 CLI、十六个独立插件仓库和十七个打包制品检查。[运行时报告](../../pr-assets/issue-250-runtime-write-scope/README.zh-CN.md)与[旧会话报告](../../pr-assets/issue-251-legacy-repair/README.zh-CN.md)保留 26 张前后对比和冷重开截图、哈希及实际验证的版本。旧会话通过真实 WebUI 续聊，同时校验发给模型的原工具 ID、参数和结果。模型响应采用确定性回环夹具。

发布流程验证版本化工作区与独立制品，只冻结两个变化的包，先发布 Memory Spaces Source，再发布 Starter；完整 Registry 安装和从 v0.4.7 开始的真实升级检查通过后，才创建 GitHub Release。
