# v0.3.5：双版本 DSH Host 兼容

**简体中文** | [English](../../en/releases/v0.3.5.md) | [能力地图](../guides/capabilities.md)

v0.3.5 在保留 DSH 0.1.1-rc.2 可复现 npm 基线的同时，新增对 GitHub-only DSH 0.1.2-alpha.1 预览版的源码兼容。同一个插件构建现在无需解析版本、检查函数参数数量或按 capability 分支，即可跨越两代 Host。

## 兼容性

- Web client 适配 alpha 拆分后的职责：Session 与 Workspace 状态继续由 controller/renderer 服务提供，renderer 接管 slots，Chat 专用 slot contract 不再依赖已移除的 owner type，Workspace 选择不再依赖 `recentWorkspaceId`，第三方 locale ID 也可安全透传。
- package 不再直接导入已移除的 `@deepseek-ai/dsh-client-runtime` 入口；DSH client 顺序依赖改为 `@deepseek-ai/dsh-client-ui-renderer`，同时保持已发布 rc.2 依赖图可复现。
- 通用 Mnemon Connection channel 继续兼容 alpha 的 ApiProxy 到 Remote/gateway 迁移，child-local 子代理 token 用量投影也继续与 DSH 完整日志指标隔离。
- Host RPC 注册统一使用一种无条件调用形态：Mnemon 始终传入 rc.2 所需的末尾 authority 对象；alpha 的双参数 JavaScript 实现会忽略额外参数，并应用统一认证的浏览器会话边界。

## 安全与升级

本次升级不需要迁移持久化数据或 Provider 数据。DSH 0.1.1-rc.2 仍会使用仅启动时读取的 `remoteAccess`：管理通道默认保持 `loopback`，只有显式配置为 `trusted-host` 时才会整体提升。DSH 0.1.2-alpha.1 会忽略该 transport 参数，并要求所有通道通过启动 token 建立的浏览器会话。保留这一设置，使同一配置既能前进到 alpha，也能回滚到 rc.2，同时不削弱 rc.2 的默认安全边界。

更新 `dsh-mnemon` 后，重启每个使用它的 DSH profile，再重新打开记忆系统界面。Registry 安装应继续使用 DSH 0.1.1-rc.2；alpha 只是源码验证目标，不是 npm 安装目标。回滚 dsh-mnemon 到 0.3.4 不需要数据转换。

## 验证

- 完整 TypeScript 与 Vitest 验证通过，共 524 项测试；本地非 Windows 环境只跳过一项 Windows 专用 smoke test。
- 真实 Connection 兼容测试会对已安装 rc.2 实现与源码链接的 alpha 实现注册同一个三参数调用。
- CI 在 Node.js 22.19 和 24 上验证 Linux，在 Node.js 24 上验证 Windows，并通过独立 Node.js 24 任务链接上游 `dsh-v0.1.2-alpha.1` tag 的精确提交 `cd5ef814`。
- 可复现双构建验证 106 个生成文件哈希完全一致；隔离的真实 Headless profile 成功激活，模型请求可见 35 个工具，其中包含 5 个代表性 Mnemon 工具。
- 发布包包含 113 个文件，packed 大小为 378,527 字节，unpacked 大小为 1,714,783 字节；10 个 Node 兼容公开入口均可成功导入，publint strict 与 attw ESM profile 全部通过。
- 发布变更通过 `git diff --check`。

兼容实现与证据见 [PR #105](https://github.com/omdsh-dev/dsh-mnemon/pull/105)；上一版 Runtime Memory 范围与容量发布见 [v0.3.4 发布说明](./v0.3.4.md)。
