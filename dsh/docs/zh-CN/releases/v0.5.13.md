# v0.5.13：工作区、Builtin 与 DSH 0.1.7 兼容修复

**简体中文** | [English](../../en/releases/v0.5.13.md)

v0.5.13 包含三项修复：

- [#268](https://github.com/omdsh-dev/dsh-mnemon/pull/268) 修复 [#266](https://github.com/omdsh-dev/dsh-mnemon/issues/266)：Windows 工作区路径如果位于普通文件之下，会在计算存储标识前以 `ENOTDIR` 拒绝。合法工作区标识、junction、Unicode 路径及尚未创建的目录后代保持原有行为；已有存储目录不会被移动或删除。
- [#269](https://github.com/omdsh-dev/dsh-mnemon/pull/269) 修复 [#265](https://github.com/omdsh-dev/dsh-mnemon/issues/265)：Builtin 记忆页打开时，仅隐藏所属对话的宽度拖拽手柄，避免手柄截获记忆页输入；返回 Chat 后恢复宽度拖拽。常驻输入框仍可使用，规则不作用于 Sidebar 或其他对话。
- [#270](https://github.com/omdsh-dev/dsh-mnemon/pull/270) 修复 [#267](https://github.com/omdsh-dev/dsh-mnemon/issues/267)：适配 DSH 0.1.7-alpha.1 基于 Config 的实时设置、新版图标导出及由生产者标识来源的 Session 消息。设置写入保留修订检查与 Profile 归属约束；历史 Mnemon 消息及官方迁移后的消息格式仍参与去重。

## 发布包与升级

本次仅将 **`dsh-mnemon` 升级至 0.5.13**。十六个配套插件及其在 Starter 中的精确版本固定均不变。Mnemon CLI 继续独立维护。

Client 的兼容下限仍为 **DSH 0.1.5-rc.1**。框架 peer 范围为 `^0.1.5-rc.1 || ^0.1.6-alpha.2 || ^0.1.7-alpha.1`；证据覆盖 0.1.5-rc.2、0.1.6-alpha.2 和 0.1.7-alpha.1，使用的公开 DSH 包均未修改。

升级前请备份 DSH Profile 配置、旧设置文件及相关 Mnemon 数据。

```sh
dsh plugin --profile web add dsh-mnemon@0.5.13
```

重启 DSH 并刷新浏览器；Headless Profile 将命令中的 `web` 替换为 `headless`。完整 DSH Profile 需要 Node `^22.19.0 || >=24.0.0`。

## 设置恢复与回滚

在 DSH 0.1.7 上，补充恢复读取保留的 `settings.yaml.imported`，不改动其原始字节。当前显式设置及原生 Strategy 选择优先于旧偏好，已有 Profile 表达式仍保留为表达式；配置重新协调后，所属 Profile 的 Source 与 Strategy 选择仍会保留。

如果启动时仍存在原始 `settings.yaml`，DSH 会先执行自己的导入。Mnemon 的补充 UI/View 恢复延后到下一次 Host 冷启动，因此升级可能需要第二次完整停止并启动 DSH。刷新浏览器或重新挂载插件不能完成这一步延后恢复。

自动恢复要求使用标准 `mnemon` 根 Entry，并精确匹配所属 Profile 的旧命名空间；不会推测自定义根 Entry 的归属或借用其他 Profile 的后缀。存在歧义或无效的输入会留在保留备份中，供人工核查。

新 Profile 设置不会回写旧设置文件。降级需要对应配置备份，并手动核对备份之后的更改；没有自动逆向导出。Runtime、Documents 和 Memory Spaces 的数据格式不变。
