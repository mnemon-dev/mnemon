# v0.4.5：Better Sidebar 兼容性

**简体中文** | [English](../../en/releases/v0.4.5.md)

v0.4.5 让已安装 `dsh-better-sidebar` 的用户可以在其中打开记忆系统，同时保留原有的 DSH 普通 Sidebar 入口。[Issue #153](https://github.com/omdsh-dev/dsh-mnemon/issues/153)、[PR #157](https://github.com/omdsh-dev/dsh-mnemon/pull/157)。

## 修复

- 默认 `displayMode: sidebar` 下，Mnemon 现在使用 Better Sidebar 文档化的可选 `registerTab` 服务。单实例 Tab 使用稳定 id `dsh-mnemon:memory`，并与 DSH 普通 Sidebar 入口复用同一个记忆系统视图。
- 注册不依赖激活顺序：Better Sidebar 可以先于或晚于 Mnemon 加载；服务替换、卸载或热重载时也会正确注销并恢复，不产生重复入口。
- Better Sidebar Tab 使用该 Tab 传入的会话和工作区作用域，不会错误沿用全局当前会话。设置 `tabEnabled: false` 或 `displayMode: builtin` 时仍不会注册此 Tab。

## 升级与兼容性

在所属 DSH profile 中安装 `dsh-mnemon@0.4.5`，然后重启。Better Sidebar 仍为可选组件，不新增运行时依赖。本次验证的兼容目标为 `dsh-better-sidebar@0.18.1-alpha.0`；未提供该服务的 profile 继续保留原有独立 Sidebar 行为。

记忆数据、存储路径、Pack 格式、Provider 凭据、RPC 权限、设置、生产依赖和会话投影状态均不变，无需迁移或删除缓存。[v0.4.4 的会话投影兼容性](./v0.4.4.md)保持不变；本补丁不包含无关的 v0.5 开发内容。

## 验证

实现与发布候选在 Node 24.18.0 与 pnpm 10.13.1 下通过完整 `pnpm run verify`：649 项测试通过，1 项 Windows 专用测试在 macOS 跳过。109 个构建文件的确定性检查、包含 35 个工具与 5 个代表性 Mnemon 工具的 Headless 激活、设置迁移与重启、10 个 Node 兼容公开入口、116 个文件的包内容、publint 和 attw 均通过。PR #157 的 Linux Node 22.19/24、Windows Node 24 和 DSH alpha 源码 CI 任务也全部通过。

两个真实隔离 WebUI profile 覆盖了两种客户端激活顺序。DSH 0.1.1-rc.2 与 `@linxin666/dsh-web-all@0.3.6` 环境先加载 Better Sidebar、后加载 Mnemon；DSH 0.1.2-alpha.3 环境先加载 Mnemon。两者都保留且仅保留 1 个普通 Sidebar 记忆系统行，Better Sidebar 菜单也仅出现 1 个入口；作用域视图正常渲染，新浏览器标签页均为 0 个控制台 error、0 个 warning。报告版本环境还通过了刷新恢复验证。详见[环境记录与截图](../../pr-assets/better-sidebar-153/README.md)。

## 回滚

在同一 profile 中重新安装 `dsh-mnemon@0.4.4` 并重启，无需转换数据。Better Sidebar 可能在自身持久化布局中保留已打开的 `dsh-mnemon:memory` Tab；回滚后它可能暂时显示为 orphaned tab，可直接关闭，原有 DSH 普通 Sidebar 入口仍可使用。
