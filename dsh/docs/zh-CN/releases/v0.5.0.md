# v0.5.0：Composable Memory Plugins

**简体中文** | [English](../../en/releases/v0.5.0.md) | [插件开发](../development/extensions.md)

v0.5.0 以 npm 正式版引入 View-based 执行模型与 Source/Strategy 扩展 SDK。插件架构主要面向开发者开放；普通用户继续沿用 v0.4 的 Sidebar 工作流。

## 范围与兼容边界

- `dsh-mnemon` 仍是单包安装的 Starter。Runtime、Documents、Memory Spaces、默认 Strategy、三个 Strategy 增强与九种 Provider 拆为十六个独立插件。三个增强随 Starter 安装但默认停用。既有存储格式、使用流程和日常工具仍是用户侧兼容约束；相对 v0.4，界面只在“设置 → 记忆系统”增加主动记录、轻量上下文、范围组合三个开关，不增加 View 页或插件管理入口。不迁移或删除记忆数据。
- Core 只暴露 `ctx.mnemonMemory`；作者通过 `dsh-mnemon/extension-sdk` 注册 Source/Strategy，通过 `dsh-mnemon/testing` 验证。Source 自有页面使用 Client SDK 与 DSH 生命周期。Memory Spaces 自己拥有 Provider SDK 与子 fiber，不增加 Core 级 Space 服务。
- Source 与 Strategy 是贡献职责，不强制分包：同一插件可在一个 Fiber 下成批注册二者。私有索引和维护仍归插件。操作保持开放，不要求统一记忆分类或摘要树。
- 每轮固定一个不可变 View。Source 操作只收到 View 身份/作用域与本 Source 的 read grant，不收到其他 Source 的投影和授权。Read grant 或 action offer 都不是写入许可。
- Source facts/projection 读取有超时边界与协作式取消。被选中的 Source 默认必需；只有显式 `required: false` 才允许缺席。故障的可选 Source 不再提供 route/action，并返回脱敏诊断解释缺席原因。公共指导跟随当前 View；自动三层复盘只属于 `default-three-tier`。

`dsh-mnemon/extension-sdk`、`dsh-mnemon/testing`、`dsh-mnemon/contracts` 以及 Source 自有 SDK 的文档化导出，是 v0.5 支持的扩展表面。官方包固定同一组已测试的 `0.5.0` 版本；外部作者应明确声明并测试兼容 peer 版本。内部路径、历史符号和 Host RPC 不属于公共扩展 API；未来 pre-1.0 次版本若调整扩展表面，会通过发布说明和迁移指引明确处理。

变更回执必须说明完成状态：已受理和候选不等于已提交记忆，只有确认提交才能携带 `committedAt`。回执辅助函数默认 `unknown`；详见[操作与结果契约](../development/extensions.md)。

## 升级与回退

升级前停止写入，备份完整有效记忆根、工作区 Documents、DSH profile/配置和单独管理的 Provider 数据。在隔离 DSH profile 中用副本验证，不将 smoke test 指向个人记忆。v0.5.0 不引入数据格式迁移。

可以显式安装正式版，也可以使用 npm `latest` 通道：

```sh
dsh plugin --profile web add dsh-mnemon@0.5.0
```

Headless profile 将 `web` 改为 `headless`，然后重启 DSH。Starter 安装匹配的十六个插件，普通用户不需要逐个安装。已经精确锁定 RC 的安装需要主动选择 `0.5.0` 才会离开预发布版本线。

采用副本前，确认原 Runtime 条目、Documents 检索/阅读、Provider 选择、召回/写入回执和设置正常。需要回退时，停止 DSH，同时恢复旧 profile 与配套数据备份，再启动。不能假定旧版本能理解第三方插件新写入的数据。

## v0.5 有意保留的边界

默认 Host 通过 `memoryTopology.strategyId` 选择一个完整 Strategy，组合 root-turn View。随附但默认停用的 `strategy-scoped`、`strategy-light-context`、`strategy-auto-capture` 可以通过该 Strategy 声明的不同槽同时贡献；用户只看到三个行为开关。同槽冲突明确报错，权限与预算仍共享，不增加后台 worker。Source/Strategy 插件契约在文档中开放并欢迎独立仓库贡献，但 v0.5 不提供通用发现、安装或依赖图界面。本版也不承诺通用多场景调度、自动发现/选择 Strategy、插件进程沙箱或自主 RSI 部署。Generation 替换与隔离作者测试为未来 RSI 提供基础，但不是自主进化闭环。外部插件执行受信任 JavaScript；取消无法抢占同步或不配合的代码。

发布门槛包括全工作区验证、所有独立插件仓库、纯 tarball 安装、外部 Source/Strategy/Provider/Client 测试、复制数据兼容、性能检查和真实 WebUI 覆盖。受控 HTTP 测试不代表所有线上 Provider 账号均已验证；固定模型响应也不衡量真实模型的记忆质量。参阅[验证与成组发布](../development/README.md)。

## 相对 RC 的变化

运行时实现、UI、配置和持久化格式相对 `v0.5.0-rc.1` 均未改变。正式版包含已用于 RC 发布路径的 Registry 校验修正，并让同一套冻结、可恢复的发布流程根据稳定语义选择 npm `latest`、创建普通 GitHub Release。

## 关联的社区需求

- `strategy-auto-capture` 为 [Issue #110](https://github.com/omdsh-dev/dsh-mnemon/issues/110) 提供可选的当前回合主动记录策略，但不引入无人监督的后台写入。
- `strategy-light-context` 针对 [Issue #40](https://github.com/omdsh-dev/dsh-mnemon/issues/40) 的上下文成本问题提供有界投影策略，但不宣称实现带 revision 的增量注入；依赖上游能力的部分继续保持开放。
- `strategy-scoped` 围绕 [Issue #77](https://github.com/omdsh-dev/dsh-mnemon/issues/77) 最初提出的全局/项目组合场景，进一步提供 Source 顺序与可写子集控制。
