# v0.2.13：DSH rc.8 兼容升级

**简体中文** | [English](../../en/releases/v0.2.13.md) | [能力地图](../guides/capabilities.md)

v0.2.13 完成 dsh-mnemon 对 DSH 0.1.0-rc.8 的兼容验证，并接入更完整的子 Agent 失败诊断；Mnemon 数据、配置与公开工具保持不变。

## 更新

- 开发与发布依赖统一锁定为精确的 DSH 0.1.0-rc.8 包族。客户端 peer 范围继续接受 rc.6 及后续兼容的 0.1 版本，rc.8 则作为推荐且完整验证的基线。
- 本地或远端子任务失败时，优先使用 rc.8 新增的有界 Provider 诊断。诊断文本仍经过既有的空白折叠、长度限制与凭据脱敏边界，之后才进入面向操作者的错误信息。
- 旧版本地子任务继续使用事件历史回退，因此本次兼容升级不强制运行时必须提供新的诊断字段。
- 快速开始补充了 rc.8 尚未进入 npm `latest` 期间通过 `@deepseek-ai/dsh@next` 安装的说明。

## 安全与兼容性

- Runtime、Documents、Memory Spaces、Provider 数据、配置键、RPC 权限与公开工具 schema 均未改变，已有 Mnemon 数据无需迁移。
- DSH rc.8 的 SQLite 不兼容调整只涉及可选的 `@deepseek-ai/dsh-session-persistence-sqlite` 会话后端。内置 profile 默认不启用，dsh-mnemon 也使用独立存储根；只有手工挂载过该后端的部署需要备份并重建对应的 DSH 会话数据库。
- rc.8 的多模态输入、文件/会话引用、命名 Codex 实例与 Windows 持久 PowerShell 会话属于 Host 能力。dsh-mnemon 现有界面继续工作，也不会扩大子 Agent 工具权限。
- 通过 `next` 标签更新 DSH、更新 dsh-mnemon，并重启受影响的 DSH profile。本版本不执行数据迁移，因此仍可正常降级插件包。

## 验证

- 本地完整验证共 370 项测试通过；Windows 专用 smoke test 只会在非 Windows 本地环境跳过。
- 真实隔离的 DSH 0.1.0-rc.8 Web profile 可加载插件，显示全部 8 个 Provider 适配器，正常渲染状态页和设置页，浏览器控制台无错误。
- 类型检查、确定性构建、Headless 激活、发布包校验、publint、attw 与冻结锁文件安装均通过。
- rc.8 UI primitives 包会产生仅限开发期的 source map 缺失警告；已发布 JavaScript、类型、构建与运行行为不受影响。

上一个补丁版本见 [v0.2.12 发布说明](./v0.2.12.md)。
