# v0.5.22：应用内更新、会话标签页与 Ollama 上的子代理

**简体中文** | [English](../../en/releases/v0.5.22.md)

本补丁版本包含 v0.5.21 之后合并的三个 PR：

- **检查版本 → 更新在桌面版中可用**（[#325](https://github.com/omdsh-dev/dsh-mnemon/pull/325)）。
  - 此前 Host 在所属 Profile 中运行 PATH 上的 pnpm 来更新 dsh-mnemon。桌面版的 Host 在 PATH 上找不到 pnpm，面板只能提示缺少 pnpm；DSH 的插件页又不能更新已安装的插件。
  - 现在更新通过 DSH 自己的插件安装器完成，效果与 `dsh plugin add dsh-mnemon@<版本>` 相同：使用 Profile 自己的包管理器（桌面版中即应用自带的 pnpm），沿用 Profile 的安装源设置、备用源与锁；安装检查到的精确版本，不受 pnpm 24 小时发布窗口的限制。Profile 单独安装的可选 Strategy 也以相同方式更新。
  - 保留新版本之前，DSH 会检查它声明支持的 DSH 版本。安装失败时恢复 Profile 的文件，面板显示 pnpm 的错误行与 DSH 的日志；已启用的插件保持不变，DSH 列出新版本后才报告成功。
  - 插件文件一变化，DSH 就会载入新的记忆系统页面，此前这会在更新报告结果之前关闭面板。现在新页面会重新打开状态页与面板，显示这次更新以及需要的重启。
  - DSH 重启之前，记忆系统每个页面的顶部都会提示已安装的版本与仍在运行的版本，无论更新来自检查版本还是 `dsh plugin`。状态页显示正在运行的版本，检查版本显示已安装的版本，不再提供 `dsh plugin` 已经安装的更新。
- **会话的 Agent 未加载时，会话标签页中的记忆系统也能使用**（[#326](https://github.com/omdsh-dev/dsh-mnemon/pull/326)）。
  - 此前 Mnemon 只能通过已加载的 Agent 找到会话所属的工作区。对于 DSH 已显示但尚未恢复的会话（例如所用 Agent 预设已不在 profile 中），状态页显示“等待工作区”，项目档案报 `memory Source is unavailable in the requested management scope`。
  - 使用工作区或集中存储时，该标签页中的运行时记忆和记忆空间用的是 DSH 启动时所在的目录；这样保存的条目仍留在那个目录中。
  - 现在 Host 通过 DSH 的工作区注册表找到会话所属的工作区，无论其 Agent 是否已加载，注册表都列有该会话。新建项目档案直接写入；项目档案已满时，由会话所属工作区中的任务 Agent 先归档最久未用的档案；新建记忆空间时也由任务 Agent 选择 Provider。这两项此前都会报“current DSH agent is not live”。
- **聊天模板要求用户查询时，记忆子代理可以自行恢复**（[#328](https://github.com/omdsh-dev/dsh-mnemon/pull/328)，issue [#327](https://github.com/omdsh-dev/dsh-mnemon/issues/327)）。
  - 在 Ollama 0.33 上使用 Qwen3.x 时，后台审查和其他记忆子代理会报 `no user query found in messages`，有时审查已经创建了项目档案。子代理唯一的用户消息是它的任务提示；工具结果填满上下文窗口后，Ollama 截断时丢掉这条提示、保留了其后的工具结果。
  - 现在服务端以这种方式拒绝子代理的请求时，Mnemon 会在这一步追加一条简短的用户消息并立即重试；该子代理之后的工具续轮也以同样的消息结尾。从不拒绝的服务端上的子代理和主会话，发出的请求与之前完全相同。调大 Ollama 的上下文长度也能避免截断。

## 升级与兼容性

支持的宿主：**DSH 0.2.0-rc.2**（npm `latest` 与 `next`）和 **DSH 0.1.7-rc.2**。完整 profile 需要 Node `^22.19.0 || >=24.0.0`。更早的宿主请继续使用 v0.5.16。

在**插件 → 添加插件**中安装 `dsh-mnemon@0.5.22`，然后选择**立即启用**。也可以使用命令行：

```sh
dsh plugin --profile web add dsh-mnemon@0.5.22
```

发布后 24 小时内请带上版本号。pnpm 11 不会选用发布不足一天的版本，在此之前普通安装或更新会得到 0.5.21，两个宿主都接受它。带版本号安装会固定版本，之后可用 `dsh plugin --profile web update --latest dsh-mnemon` 升级。

- **已有安装：**发布后 24 小时内运行 `dsh plugin --profile web add dsh-mnemon@0.5.22`，之后 `dsh plugin --profile web update dsh-mnemon` 即可（带版本号安装的用 `update --latest`），然后重启 DSH。
- **桌面版：**DSH 的插件页不能更新已安装的插件，0.5.21 及更早的版本也无法在桌面版中自行更新。请更新一次：在插件页移除 dsh-mnemon，再添加 `dsh-mnemon@0.5.22`，然后完全退出应用并重新打开，记忆数据会保留。从 0.5.22 起，可在**记忆系统 → 状态 → 检查版本 → 更新**中安装之后的版本。
- **重启提示：**它由正在运行的 Host 报告，因此从 0.5.22 再更新时才会出现。从旧版本装上 0.5.22 后，请照常重启 DSH。

无需迁移记忆数据或配置。
