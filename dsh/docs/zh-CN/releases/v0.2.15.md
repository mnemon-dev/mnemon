# v0.2.15：DSH rc.2 兼容与更稳健的任务 Agent

**简体中文** | [English](../../en/releases/v0.2.15.md) | [能力地图](../guides/capabilities.md)

v0.2.15 完成对 DSH 0.1.1-rc.2 的验证，让多模态 Host 内容安全经过现有生命周期而不存储图片字节，并包含 v0.2.14 之后合并的任务 Agent 与高级布局修复。

## DSH 0.1.1-rc.2 兼容

- 10 个直接 `@deepseek-ai/dsh*` 开发依赖均精确固定到 0.1.1-rc.2。lockfile 与官方发布依赖图一致：未改动的内部包会有意保留在 rc.1，且不包含更旧的 DSH 预发布版本线。
- 对外的 UI-primitives peer 范围继续接受兼容的 0.1.0 Host，也接受从 rc.1 开始的 0.1.1 预发布版本线（包括 rc.2）。
- 实时模型目录现在保留 DSH `inputModalities`。设置页会把第一方 `deepseek-official/deepseek-v4-flash-vision-exp` 路由标记为**图片输入**。
- 生命周期处理接受 DSH 持久图片 attachment 引用，追加指引时保留所有原始内容块，活动阈值只计算文本。Mnemon 的后台元信息、召回、写入、沉淀、选择与归档任务仍为纯文本。
- DSH rc.2 优先复用 DeepSeek Files API 上传，并根据选定模型规范化图片尺寸与格式。这些上传仍由 DSH 管理；dsh-mnemon 不会把原始图片字节复制进运行时记忆、项目档案或记忆空间。

## 修复

- 配置的后台任务 Agent 模型路由现在会传到 coordinator 的每一次委托，包括空闲复盘、召回、写入、问答、Provider 选择、迁移、USER 压缩、档案归档和元信息维护。
- 元信息维护会跳过标题或描述不满足本地长度边界的模型候选；同一结果中的有效候选仍会应用，被省略的记忆空间保留现有元信息，而意外或重复的标识仍会直接失败。
- 侧边栏入口发现和工作区接管现在同时识别 DSH 高级模式 frame class 与经典 pane 布局。

## 安全与升级

- Mnemon 持久化格式、RPC 权限、凭据处理、公开工具 schema 和数据迁移均无变化。
- 发布包保持 v0.2 表面：只包含根插件、Client wrapper 与 package metadata，不包含 v0.3 kernel、topology、workspace package 或 SDK 入口。
- 发布包继续为较旧且兼容的 DSH Host 保留 Node.js `>=20` engine。完整 DSH 0.1.1-rc.2 profile 需要 Node.js `^22.19.0 || >=24.0.0`，因为 Host 使用 `Promise.withResolvers` 和 Node Zstd API。
- 可选的 DSH SQLite 会话后端与 Mnemon 存储相互独立，且使用 schema 17。手工启用它的部署需要遵循上游备份与重建要求；内置 profile 默认不启用。
- 更新 DSH 与 dsh-mnemon 后，重启每个受影响的 profile。降级 package 不需要回滚 Mnemon 数据。

## 验证

- 完整 `pnpm run verify` 链共 380 项测试通过；Windows 专用 smoke test 只在本地非 Windows 环境跳过。
- 双构建的 65 个生成文件完全一致；隔离 Headless 激活暴露 35 个总工具，其中 5 个代表性 Mnemon 工具全部存在。
- 发布包校验共 72 个文件，只保留 v0.2 根入口和 Client 代码入口；publint strict 与 attw 通过。
- 发布前检查 frozen lockfile 安装和 package version/tag 一致性。
- GitHub CI 覆盖 Ubuntu Node.js 22.19 与 24，以及 Windows Node.js 24。
- DSH UI primitives 只产生已知的开发期缺失 source map 警告。
