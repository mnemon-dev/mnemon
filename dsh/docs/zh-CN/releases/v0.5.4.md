# v0.5.4：统一记忆空间表达

**简体中文** | [English](../../en/releases/v0.5.4.md)

v0.5.4 将持久化记忆单元统一称为 **记忆空间**，英文对应 **memory space**。本版包含 [PR #194](https://github.com/omdsh-dev/dsh-mnemon/pull/194)，覆盖产品文案、代码模型、公开 SDK 命名、响应式布局和文档。

## 统一表达与界面布局

- 工作台、设置、无障碍标签、Agent 指引、命令输出、随包 README 和双语指南使用一致术语。单条记忆、运行时记忆和项目档案继续保留各自含义。
- 代码规范命名包括 `MemorySpace`、`MemorySpaceRegistry`，以及 `createSpace`、`mergeSpaces` 等服务操作。
- 窄屏目录操作在可用宽度内换行，Provider 状态标签与存储标识允许换行，导航间距适配更长的标签。中英文目录与创建流程均在 390 × 844 下检查。
- 当前文档使用更新后的桌面和窄屏截图。可编辑的中文示意图采用新术语；历史截图、测量和录屏保留原始像素及来源记录。

## 兼容性与现有数据

既有 v0.5.x 集成继续可用。旧模型名称与服务方法保留为兼容别名；Provider factory 在旧上下文之外接受规范 authority 名称，HTTP Provider 的旧 protected 字段继续兼容现有子类。

已发布的工具/RPC 名称、`memoryBodyId(s)` 等 wire 字段、registry 文件名与 JSON 结构、Document/Pack lineage 和 revision 编码沿用原有拼写，这些标识仍指记忆空间。用户自行设置的名称保持原样，包括使用旧中文术语的名称。不需要迁移数据；ID、数据位置、Provider 连接、管理授权与只读限制保持兼容。

## 发布包与升级

Starter 和全部十六个官方插件均升级到 `0.5.4`，因为各包都有代码或随包文档变化。独立版本机制继续生效，Starter 精确固定这组经过验证的组合。

在实际使用的 DSH Profile 中安装，然后重启 DSH：

```sh
dsh plugin --profile web add dsh-mnemon@0.5.4
```

Headless Profile 将 `web` 替换为 `headless`。Mnemon CLI 继续独立维护，本版不修改其版本；安装和更新指引继续采用官方 `@mnemon-dev/mnemon` npm 包。参见[快速开始](../guides/getting-started.md)与[运维指南](../guides/operations.md)。

回滚时，在同一 Profile 安装 `dsh-mnemon@0.5.3` 并重启 DSH，无需转换数据。若另行更新了独立安装的插件，需要分别恢复。

## 验证与证据

实现已通过 783 项根测试、300 项插件测试、确定性构建、工作区类型检查、真实隔离 DSH Headless 激活、包检查，以及十六个插件独立仓库和十七个 tarball 的验证。外部 SDK 夹具同时编译新旧模型名称，并验证覆写旧 protected Provider 字段的子类。两项 opt-in Native/平台实机集成测试需要单独环境，本地已跳过。

[真实双语 UI 证据](../../assets/memory-space-terminology/README.md)使用可丢弃的合成数据，覆盖创建、编辑、激活、浏览、设置、语言切换和取消。十八张原始 JPEG 截图在版本化之前采集，基于 v0.5.3 加入本次实现；这些改动现已纳入 v0.5.4，截图版本标识对应采集时的基线。未评估模型质量或云端 Provider 行为。窄屏修复不代表已经覆盖所有设置页面，其他[已记录的兼容性限制](../reference/compatibility.md)仍适用。

发布流程验证版本化工作区和独立包，冻结制品完整性，先发布插件依赖层、后发布 Starter，从 npm 安装完整组合，并在创建 GitHub Release 前对从 v0.4.7 升级执行 Registry 冒烟测试。
