# v0.5.10：精确记忆写入与自动审阅限制

**简体中文** | [English](../../en/releases/v0.5.10.md)

v0.5.10 包含 [#256](https://github.com/omdsh-dev/dsh-mnemon/pull/256) 的 Runtime 匹配修复、[#234](https://github.com/omdsh-dev/dsh-mnemon/pull/234) 的 OpenViking 写入验证，以及 [#257](https://github.com/omdsh-dev/dsh-mnemon/pull/257) 的自动审阅限制与 Agent Teams 兼容处理。

## Runtime 与 OpenViking 写入

Runtime 替换和删除优先匹配唯一的完整内容，再尝试唯一的子串匹配。因此，仅含 `X` 的条目可以与 `EGO_LINUX_CHROME` 共存并正常编辑或删除。重复的完整匹配仍要求消除歧义，拒绝操作时保留已有数据。

OpenViking 将原文写入唯一的新文件，验证索引状态和内容逐字回读后，再返回用于 Host 回执与归档补偿的作用域内文件身份，不再把提取响应当作原文已存储的证明。搜索和浏览返回完整内容。账户隔离、旧 owner-root 解析和删除范围均经过验证；未完成或结果不确定的写入会返回包含候选 URI 的错误。合并历史保留原贡献者的提交。缺少所需内容写入与读取契约的服务器会明确报错，不迁移设置或既有内容。

## 自动审阅

自动审阅具有独立开关，默认最小间隔为五分钟，每个已加载的父 Agent 最多尝试 20 次。默认 spawn 路径限制上下文大小；fork 需要显式选择，可在子 Agent 启动前回退或跳过。单次模型响应的 token 上限不等于整个任务的用量上限。Agent 卸载或 Host 重启后，尝试预算重新计算；既有会话历史保留。

同时启用受影响的已发布 Agent Teams 服务和工具时，自动审阅会在创建子 Agent 前暂停，并说明组合不兼容的原因。这一处理避免自动审阅触发故障，并未修复上游 Team 策略或手动委派。失败的审阅可以展示已经提交的写入回执，便于核对，不会重放整个任务。

```sh
dsh plugin --profile web add dsh-mnemon@0.5.10
```

重启 DSH 并刷新浏览器；Headless Profile 将命令中的 `web` 替换为 `headless`。完整 DSH Profile 需要 Node `^22.19.0 || >=24.0.0`。

## 验证

整合实现通过 1,162 项根包测试，5 项 opt-in 跳过，并通过插件测试、真实 Mnemon 0.2.8 CLI、Headless 激活与重启、确定性构建和公共包检查。十六个独立插件、十七个制品通过安装与组合验证，包含同时启用三个可选 Strategy 扩展。真实 OpenViking 0.4.20 通过创建、读取、搜索和删除检查；已发布 DSH 0.1.5-rc.2 与 Agent Teams 0.1.5-alpha.2 的组合矩阵验证了兼容性暂停。
