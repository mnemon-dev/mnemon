# v0.3.2：确定性运行时与托管嵌入配置

**简体中文** | [English](../../en/releases/v0.3.2.md) | [能力地图](../guides/capabilities.md)

v0.3.2 从三个方面加强 v0.3 可组合记忆版本线：Runtime 容量恢复改为确定且由 Host 掌控，Mnemon Native 嵌入配置无需 shell 设置即可在桌面会话中生效，不变的 Runtime Memory 协议也不再随每次变化重复进入动态上下文尾部。

## 更新内容

- Runtime 容量恢复在只有一个可写记忆空间时不再调用模型；存在多个目标时，worker 只接收有界摘录用于路由。Host 按目标批量导入未经改写的原始条目，为每个 source 校验唯一终态回执，通过 revision fence 后再按确定性规则保留热记忆并提交待处理变更。外部只完成部分写入时，本地 Runtime 原文保持不变且可安全重试。[PR #78](https://github.com/omdsh-dev/dsh-mnemon/pull/78) 由此解决 [Issue #70](https://github.com/omdsh-dev/dsh-mnemon/issues/70)。
- Mnemon Native 设置现在可由 DSH 管理兼容 Ollama 的嵌入 Endpoint 与模型。保存值只注入 Mnemon 子进程，因此从 Finder 或 Dock 启动的 macOS 会话不再依赖 shell 文件、`launchctl` 或 LaunchAgent。真实的 `mnemon embed --status` 检查会展示服务可达性、实际模型与 Store 覆盖率。[PR #79](https://github.com/omdsh-dev/dsh-mnemon/pull/79) 由此解决 [Issue #69](https://github.com/omdsh-dev/dsh-mnemon/issues/69)。
- 3,450 字节的不变 Runtime Memory 读写协议现在位于稳定的 system-prompt section。动态 runtime context 仍是完整替换快照，包含 revision、条目数、UTF-8 用量以及 USER.md 与 MEMORY.md 原文；移动协议和原分隔符后，每个发生变化的动态尾部减少 3,452 字节，同时没有引入脆弱的增量链。[PR #80](https://github.com/omdsh-dev/dsh-mnemon/pull/80) 完成 [Issue #40](https://github.com/omdsh-dev/dsh-mnemon/issues/40) 的安全第一阶段；上游增量上下文能力仍由保持开放的 Issue 继续跟踪。

## 兼容性与升级

Runtime、档案、记忆空间、Provider、配置、RPC 与工具均没有需要迁移的持久化格式变更。新增托管嵌入配置默认关闭；省略或禁用时，现有继承环境保持完全不变。启用后，Mnemon 会把记忆与查询正文发送到配置的 Endpoint；远程部署应使用可信 HTTPS 服务。Endpoint 输入拒绝凭据、查询字符串与片段，状态操作也不能为单次调用选择任意目标。

Runtime 投影继续使用最新完整快照替换，保留 resume、fork、compaction、删除与上下文裁剪语义。Provider 批量写入接口为可选能力，现有 Provider 继续回退到逐条 `remember`。更新 `dsh-mnemon` 后重启每个使用它的 DSH profile，再重新打开记忆系统界面即可。回滚到 `0.3.1` 不需要反向迁移。

## 验证

- 完整 TypeScript 与 Vitest 验证通过，共 485 项测试；本地非 Windows 环境只跳过一项 Windows 专用 smoke test。
- 可复现双构建验证 103 个生成文件哈希完全一致。
- 隔离的真实 Headless profile 成功激活，模型请求可见 35 个工具，其中包含 5 个代表性 Mnemon 工具。
- 发布包包含 110 个文件，unpacked 大小为 1,673,026 字节，低于强制的 1,680,000 字节上限；10 个 Node 兼容公开入口均可成功导入，publint strict 与 attw ESM profile 全部通过。
- 官方 Mnemon v0.2.3 Native CLI 往返验证保留高密度归档 source 原文；官方 Mnemon v0.2.5 状态集成同时确认保存的 Endpoint 会覆盖冲突的继承值，并报告实际嵌入模型。
- 发布变更通过 `git diff --check`。
