## 运行时归档

任何写入开始前，归档目标必须支持精确同步写入和安全删除。Host 再次核对所有目标及当前 Runtime revision，按目标保留回执，并且仅补偿清理能够证明本次新建的条目。去重或更新的记录会被保留，本地提交结果不确定时也不会删除归档副本。

无效路由提案按整批回退到经过验证的默认目标，保留此前有效批次和完整原文。路由期间被停用的目标会在 Provider 写入和 Runtime 变更之前被拒绝。若 Provider 已部分写入远端后抛错，却没有返回任何回执，仍无法保证跨存储回滚。

## 委派审查与 WebUI

- 在 Host 生命周期内固定结果工具名称与结构。每次运行使用可撤销请求，校验子 Agent 归属、结果结构、取消、并发隔离与卸载。
- 复用完整继承的审查证据。子 Agent 执行守卫覆盖其他插件直接注册的工具及 Code Mode 子调用；证据不完整时仍可进行有界的档案搜索。
- 在记忆系统工作区和 Host 日志中显示后台审查失败。警告跨普通轮次保留，直到审查成功或会话重置；上下文窗口错误提供处理提示。
- 让 Mnemon 侧栏入口在 ORCA LINK 皮肤下保持可见、可点击，覆盖侧栏收起布局。

本版验证了工具定义保持稳定，不声称测得模型缓存命中、token 节省或费用降低。

## 包版本与升级

仅 `dsh-mnemon` Starter 从 `0.5.7` 升级为 `0.5.8`，使用 npm 的 `latest` 通道。十六个独立版本插件保持已验证版本：Runtime、Documents、Memory Spaces Source 为 `0.5.6`；Mnemon Native Provider 和 Default Three-tier Strategy 为 `0.5.5`；其余十一个为 `0.5.4`。Mnemon CLI 继续独立维护。

```sh
dsh plugin --profile web add dsh-mnemon@0.5.8
```

重启 DSH 并刷新浏览器；Headless Profile 将 `web` 换成 `headless`。完整 DSH Profile 需要 Node `^22.19.0 || >=24.0.0`。已有存储格式和支持的 DSH peer 范围保持兼容。
