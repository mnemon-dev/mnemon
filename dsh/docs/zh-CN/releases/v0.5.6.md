# v0.5.6：内置工作区存储与记忆可靠性

**简体中文** | [English](../../en/releases/v0.5.6.md)

v0.5.6 在 Core/Host 中加入集中式工作区存储，并包含 v0.5.5 之后合并的记忆可靠性修复：[#216](https://github.com/omdsh-dev/dsh-mnemon/pull/216)、[#212](https://github.com/omdsh-dev/dsh-mnemon/pull/212)、[#213](https://github.com/omdsh-dev/dsh-mnemon/pull/213)、[#214](https://github.com/omdsh-dev/dsh-mnemon/pull/214) 和 [#199](https://github.com/omdsh-dev/dsh-mnemon/pull/199)。

## 集中式工作区存储

在设置 → 记忆系统中选择**集中工作区**。Core/Host 将 Runtime、Documents、Memory Spaces 和 state 路由到 `<central-root>/workspaces/<sha256(canonical-workspace-path)>/`。可选根目录接受绝对路径或用户主目录相对路径；清空后使用 `MNEMON_DATA_DIR` 或 `~/.mnemon`。独立的 USER.md 设置仍可保留全局用户档案。

该能力内置于主包。Sidebar 检查所选的已注册工作区，Builtin 与 Headless 操作跟随所属会话。已有符号链接别名共享身份，移动或重命名工作区则选择新身份。切换范围保留旧数据，不自动迁移、合并或删除；远程 Provider namespace 保留自身的共享语义。详见[配置](../reference/configuration.md#workspaces)。

较长的记忆空间路径现在限制在当前列宽内；标签换行时，工作区选择与对齐操作仍然可用。

## 记忆与 CLI 修复

- 默认 Strategy 对命名工具、通用 Action、子 Agent 和浏览器管理统一执行 Runtime 容量归档。维护过程保留所选 Source、namespace、revision 检查与排队回合的所属关系。
- Native 批量归档保留不同但相似的事实，仅复用完全相同的已有内容，并在 Runtime 压缩前验证导入回执。Host 与 Memory Spaces 的子进程读取保留跨输出块的 UTF-8 字符。
- 自主写入 worker 不再调用 `mnemon_forget`；空闲审阅可创建独立 Document，但不能覆盖或归档已有 Document。用户显式操作保留写入工具，失败的 forget 回执不再声称删除成功。
- Runtime 条目，以及活动、归档和搜索中的 Documents 均按创建时间从新到旧排列，加载更多之前也保持此顺序。编辑旧条目不会改变其创建日期。
- Electron Host 下经验证的 npm JavaScript 启动器以 Node 模式运行，修复 CLI 版本检测、记忆操作、归属检查和更新，同时保留 embedding 覆盖配置与原生可执行文件行为。

## 包版本与升级

| 包 | 版本 |
|---|---|
| `dsh-mnemon` | `0.5.6` |
| `dsh-mnemon-source-runtime` | `0.5.5` |
| `dsh-mnemon-source-documents` | `0.5.5` |

| `dsh-mnemon-strategy-default-three-tier` | `0.5.5` |

其余十一个官方插件仍固定为 `0.5.4`。Starter 安装经过验证的十六插件精确组合。Mnemon CLI 仍通过 `@mnemon-dev/mnemon` 独立维护。

```sh
dsh plugin --profile web add dsh-mnemon@0.5.6
```

重启 DSH 并刷新浏览器；Headless Profile 将 `web` 换成 `headless`。DSH 基线保持 0.1.2-rc.1，完整 profile 需要 Node `^22.19.0 || >=24.0.0`。

已有存储格式保持兼容，启用新范围不会移动已有记忆。Pack 仅导出当前选中的根目录；如需保留所有工作区，应备份整个集中目录。回滚到 `dsh-mnemon@0.5.5` 前，请从新的 `workspaces` 范围切换到旧版支持的布局并保留备份。旧根目录仍留在磁盘上；回滚不会合并不同根目录中的数据。
