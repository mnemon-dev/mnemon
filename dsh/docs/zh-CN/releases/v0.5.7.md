# v0.5.7：DSH 0.1.5 兼容与文档归档

**简体中文** | [English](../../en/releases/v0.5.7.md)

v0.5.7 修复 DSH 0.1.5-rc.1 下记忆系统的 HTTP 405，提供受影响旧会话的显式副本修复工具，并使用 Host 验证的回执完成文档归档。包含 [#226](https://github.com/omdsh-dev/dsh-mnemon/pull/226) 和 [#224](https://github.com/omdsh-dev/dsh-mnemon/pull/224)。

## DSH 兼容与旧会话

Starter 补充已发布 DSH 0.1.5-rc.1 Profile 注册记忆系统 RPC 所需的 Connection 依赖。设置、状态和 Source 操作通过正常的鉴权传输加载。保留此前支持的 DSH peer 范围，开发与发布检查使用已发布的 0.1.5-rc.1 依赖族。

新生成的 Mnemon recall 和 instructions 消息不再包含会被 DSH 会话迁移拒绝的旧 summary 元数据。新增 `dsh-mnemon-repair-session` 命令，可预览受影响的 v0 JSONL 或 JSONL.zstd 文件，并写入独立修复副本。它仅移除两个已知的历史 Mnemon summary 字段，保留其余解码字节，并拒绝覆盖文件或处理不支持的输入。

已有会话不会被自动修复。先停止 DSH、备份整个会话根目录，再遵循[旧会话修复流程](../guides/operations.md#dsh-015-兼容与旧会话恢复)。先验证副本，再显式替换会话；后续格式迁移由 DSH 自身完成。保留原始备份用于回滚。普通 JSONL 修复支持 Node 20，压缩文件修复需要 Node 22.19 或受支持的更新 Node 版本。

## 文档归档

归档 worker 只提出索引摘要和一个现有的可用记忆空间，不写入数据。Host 在索引前验证提案与当前访问策略，补充精确的冷存储路径和内容 hash，并使用自身的持久回执构建 lineage。无效提案会让文档保持 active，且不产生索引。

完全匹配的已有索引可以复用。归档文档提交失败时，Host 补偿清理新建的索引。归档弹窗说明目标必须支持同步写入和删除，操作期间切换为只读也会被执行逻辑尊重。文档原始内容继续保存在冷存储中。

## 包版本与升级

| 包 | 版本 |
|---|---|
| `dsh-mnemon` | `0.5.7` |
| `dsh-mnemon-source-runtime` | `0.5.6` |
| `dsh-mnemon-source-documents` | `0.5.6` |
| `dsh-mnemon-source-memory-spaces` | `0.5.6` |

Mnemon Native Provider 和 Default Three-tier Strategy 保持 `0.5.5`，其余十一个官方插件保持 `0.5.4`。Starter 固定完整的十六插件组合。Mnemon CLI 仍通过 `@mnemon-dev/mnemon` 独立维护。

```sh
dsh plugin --profile web add dsh-mnemon@0.5.7
```

重启 DSH 并刷新浏览器；Headless Profile 将 `web` 换成 `headless`。完整 DSH 0.1.5-rc.1 Profile 需要 Node `^22.19.0 || >=24.0.0`。Runtime、Documents 和 Memory Space 存储格式保持不变。降级 Mnemon 不会撤销 DSH 的会话迁移；回到旧版 DSH 时应使用保留的迁移前备份。
