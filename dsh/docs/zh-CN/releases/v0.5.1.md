# v0.5.1：Desktop 与回合可靠性

**简体中文** | [English](../../en/releases/v0.5.1.md)

v0.5.1 是 `dsh-mnemon` Starter 与十六个官方插件的协调补丁版本。它修复两个在稳定版 DSH 0.1.2-rc.1 上复现的问题，并保持 v0.5.0 的可组合架构、配置、扩展表面与已有数据不变。

## 修复

- Desktop launcher 现在通过正式 Sidebar 新会话控件的实际父元素插入。嵌套的 `dshp-panelArea` 不再触发 `insertBefore` `NotFoundError`，该挂载异常也不会再把记忆系统设置页级联降级为只读。[Issue #176](https://github.com/omdsh-dev/dsh-mnemon/issues/176)、[PR #177](https://github.com/omdsh-dev/dsh-mnemon/pull/177)。
- 普通用户回合开始前会中止并等待进行中的 Idle Review 完成清理，再创建新的 Turn View 并绑定 Agent runtime；清理后还会重新检查 abort 与 turn 状态。这样既保留 runtime 独占所有权，也不会再用 `already pinned` 拒绝用户回合。[Issue #172](https://github.com/omdsh-dev/dsh-mnemon/issues/172)、[PR #178](https://github.com/omdsh-dev/dsh-mnemon/pull/178)。

## 升级与兼容性

在所属 DSH profile 中安装精确稳定版并重启：

```sh
dsh plugin --profile web add dsh-mnemon@0.5.1
```

Headless profile 将 `web` 改为 `headless`。Starter 会安装全部十六个匹配的 `0.5.1` 插件，普通用户不需要逐个安装；稳定 npm 通道仍是 `latest`。

本版本不迁移配置、RPC 权限、凭据、存储路径、记忆格式、Document 格式、Provider 数据或扩展契约，现有 v0.5.0 profile 与数据可直接使用。与任何升级一样，请先停止写入并备份有效记忆根、工作区 Documents、DSH profile/配置和单独管理的 Provider 数据。

## 验证

两个问题都先在一次性的真实 DSH 0.1.2-rc.1 WebUI profile 中复现。修复后的 Desktop profile 保持设置可写并成功保存 `storageScope=workspace`；修复后的生命周期 profile 在刻意挂起 Idle Review 时仍正常完成第三轮对话。两个实现 PR 都保留了修复前后截图，夹具仅使用合成数据。

Sidebar/设置与生命周期定向回归通过，随后完成整个 workspace 验证。发布流水线还会验证确定性构建、Node 20 全部公开入口、十七个 packed 制品、十六个独立安装的插件仓库、外部 SDK 消费者、真实 packed DSH 组合，以及基于 Registry 的 v0.4.7 升级。PR CI 收敛为两个互补重型 job 与有界四 worker 制品队列，同时不删除这些发布门禁。[PR #179](https://github.com/omdsh-dev/dsh-mnemon/pull/179)。

## 回滚

在同一 profile 中重新安装 `dsh-mnemon@0.5.0` 并重启 DSH，无需转换数据；但嵌套 Desktop 设置故障与 Idle Review pin 竞态可能再次出现。如果升级后已发生写入，应恢复与旧版本匹配的升级前 profile/数据备份。
